- **Crew update keeps the `agent` account (#5337).** Crew update now injects common-utils with `agent` at UID/GID 1001 the same way crew create does, so `crewship crew config --devcontainer` and `PATCH /crews/{id}` with a bare base image no longer build a container without the runtime account. `crewship apply` (both `kind: Crew` and crews in a legacy manifest) compares the manifest's devcontainer with the stored config in that settled form: re-applying the manifest that created a crew plans no update, where it used to PATCH the bare config and strip the account. Create and update keep config keys Crewship does not model (`hostRequirements`, `customizations`) when they add the account. Some existing crews get one update on the next apply and build once: those whose stored config lost the account, still has the old `uid`/`gid` names, or was re-marshalled without unmodelled keys at create. A crew on a prebuilt image with `agent` at 1001 and no features now gets a feature build after its next config change, as at create; declare common-utils with `username: none` to skip it.

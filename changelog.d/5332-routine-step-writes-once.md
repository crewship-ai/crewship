- **A routine `crewship` step could write twice after a crash, and one approval could authorise both writes.** The executor saves a step's output after the route writes. A crash between the two re-ran the step on resume. Only chat-origin issue writes were deduplicated, so a scheduled, webhook or manual run could create a second issue, comment, link, assignment or escalation. A held action's approval stays `approved`, so the second call also passed it. Each of these six routes now records the step's operation key in the same transaction as its write. A resumed or retried call gets the first answer back and writes nothing. If the arguments render differently on resume, the step fails with `409 step_key_conflict`.

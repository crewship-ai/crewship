- **Crew update keeps the `agent` account (#5337).** Crew update now injects common-utils with `agent` at UID/GID 1001 the same way crew create does, so `crewship crew config --devcontainer` and `PATCH /crews/{id}` with a bare base image no longer build a container without the runtime account. `crewship apply` (both `kind: Crew` and crews in a legacy manifest) compares the manifest's devcontainer with the stored config in that settled form: re-applying the manifest that created a crew plans no update, where it used to PATCH the bare config and strip the account. Create and update keep config keys Crewship does not model (`hostRequirements`, `customizations`) when they add the account. A crew whose stored config already lost the account gets one update on the next apply and builds once.

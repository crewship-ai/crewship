- **Installed native tools were missing from interactive terminals.** The terminal uses shared native paths, including persistent crew tools, and reads only PATH from container metadata. Metadata failures omit the exec PATH override so the terminal opens with the full inherited container PATH. Agent-run credentials are not copied; new images restore native paths for POSIX login shells and verify global mise installations outside project configuration.
- **Image cache migration:** the generated login hook invalidates crew image cache keys on its next provision. The next provision builds a new crew image even with unchanged declarations; underlying feature/Docker layers may be reused. Running containers retain their image until normal activation.
- ⚠️ **Behaviour change:** interactive Bash starts in non-login mode. Login-only feature initialization and production agent-shell acceptance remain open in #5458/#5452. Persistent user binaries can still shadow mise selections (#5459).
- **Runtime PATH precedence is shared.** Provisioning, Docker, explicit Apple runtime PATH and terminal exec complete PATH through one function and one directory list. Existing operator order is preserved (including mise shims before user-local bin); only missing entries are prepended. This reverts the intermediate fixed reordering in this unreleased fix; general persistent-home shadowing remains open in #5459.
- ⚠️ **Behaviour change: agent and routine commands can select a different installed version after rebuild/recreation.** Docker no longer unconditionally puts pipx/npm-global directories before the image's native tool paths. Newly provisioned image defaults can therefore select a mise version instead of a same-name feature-installed CLI. Crews intentionally using the feature version must declare their preferred PATH order. Existing containers retain their stored environment, and recreating from a legacy image can still produce a different order from a newly provisioned image; matching executable selection across image generations is not guaranteed.
- **Docker image PATH recovery is retained for tool-only inputs.** Configured/captured paths containing only shared tool directories append the image PATH so system utilities remain reachable; the shared classification now includes crew-tools. A genuinely custom PATH keeps its existing restriction.

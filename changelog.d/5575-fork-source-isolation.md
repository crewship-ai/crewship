- **A forked restore (`backup restore --as-workspace` / `--as-crew`) no longer writes rows into the source workspace or leaves the fork pointing at source rows.** Columns stored as plain text instead of a declared foreign key kept the source's ids. A fork added a duplicate notification channel, notification preference or automation to the source and none to the fork. The forked agent's MCP binding still named the source integration. Agent-assigned issues, recurring issues and triage rules kept the source agent, crew and agent budgets capped the source's rows instead of the fork's, and journal entries named the source crew, agent and issue. Those columns now follow the fork. A second remap edge on a polymorphic column was also dropped, so crew-scope MCP bindings were not rewritten. Automations and notification channels land enabled in the fork, so disable one copy when forking beside a live source (#5575).

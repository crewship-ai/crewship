- **A Sheet can be created from an .xlsx workbook, and large Sheets can be saved.** `crewship craft import <page> --file book.xlsx` converts the workbook with the document engine in a separate, killable worker process and publishes it as a new native Sheet in an empty page you own; the file is only read and an existing Sheet is never replaced. A workbook the engine would read only in part (a sheet over 1 000 000 XML elements) is refused with a reason instead of being imported shortened. The editor now compacts a large Sheet export before hashing and saving it and sends large saves gzip-compressed; a Sheet over 32 MiB compact is not sent and the editor says so. Documents opened in the engine through a held session answer in milliseconds instead of re-opening the workbook for every command.
- **The document engine of Word and Sheet now runs in a worker process.** A run that overruns its deadline, its output limit or its memory is killed instead of being polled for cancellation; opening a 235 000 cell workbook takes about 26 s instead of 122 s, which is what a save and an agent run need to stay under their 60 s deadline. Where a worker cannot start (no writable temporary directory, a binary that is not the server), Crewship logs one warning and falls back to the in-process engine, and the application's diagnostics report `runtime`, `degraded` and `degraded_reason`. `CREWSHIP_CRAFT_ENGINE_INPROCESS=1` keeps the earlier behaviour. See "Where the document engine runs" in the artifacts configuration.
- **A newer Sheet editor opens existing Sheets and a rollback keeps working.** The store accepts the editor of the previous release as compatible for the same engine and never rewrites a document's pin; new Sheets are written with the previous pin, so the previous release can still open them. The editor gained `gridcraft:execute` (a fixed list of value commands, one undo step), so an agent's change can appear in an open Sheet without reloading it.

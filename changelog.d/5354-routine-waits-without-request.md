- **Routine runs no longer hold an HTTP request open while a person decides (#5354).** A held action or approval inside a routine that was called by another routine, a replay, a schedule's "run now", a batch item or an agent's `run_routine` now returns the same `WAITING` receipt a synchronous run returns, with the run the caller started (the parent run for a called routine). In a batch, a waiting item is reported as `WAITING` with its token and the rest of the batch goes on; the CLI shows it apart from successes. The run continues without the request and stops, as before, when the server stops or the run is cancelled; before the approved action runs it now also checks that the person who started the run and the routine still exist. A client that leaves before anything waits still cancels the run.
- ⚠️ **Behaviour change:** these endpoints can now answer `200` with `status: "WAITING"` (plus `waitpoint_token` and `current_step`) instead of waiting for the decision.
- ⚠️ **Behaviour change:** a run that waited for a person now re-checks, before the approved action runs, that the person who started it is still a member and that the routine still exists and is active. If not, the run fails and the action does not run. Before, it ran anyway.

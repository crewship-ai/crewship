- **On macOS (Apple container runtime), credential environment values no longer show up in the host process list (#5497).** Every exec passed its environment as `container exec --env KEY=value`, so any user on the Mac could read API tokens and other credentials with `ps`. Values now reach the `container` CLI through an anonymous pipe (`--env-file /dev/fd/3`). A value the env-file parser would not carry byte-for-byte (one that contains a line break, is invalid UTF-8, or starts with a non-ASCII character) goes through the CLI's own process environment with a bare `--env KEY`. Only variable names stay on the command line. ⚠️ **Behaviour change:** an exec that carries environment variables now needs `container` 1.0.0 or newer and is refused on older or unreadable CLI versions. Names that are not ASCII identifiers (`[A-Za-z_][A-Za-z0-9_]*`) are refused. So are names the CLI itself reads (`CONTAINER_*`, `PATH`, `HOME`, `DYLD_*` and similar) when their value would need the fallback. The Linux Docker runtime is unchanged.

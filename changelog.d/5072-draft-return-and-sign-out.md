- **A Word, Sheet or Project draft stayed on screen after you returned to a tab whose read access had ended.** The editor kept showing while its access check ran. On a return to the tab or to the network it now leaves the screen before the browser paints and comes back only with a read asked after that return, with focus and typing position kept. If the check takes more than a second, the page says so. ⚠️ **Behaviour change:** every return to a tab blanks the draft for the length of that check.
- **A draft could survive a confirmed sign-out when writing the sign-out record failed.** A tab still holding the draft wrote it after the erase, and nothing removed it. The record now goes to local storage first, so that write stores nothing and the next page load finishes the job.
- **Losing Edit on an open Sheet in Chrome could end in "Zachycení posledních změn nebylo potvrzeno".** The editor was hidden before it was asked for its last changes, and Chrome stops rendering a hidden frame. It now stays transparent until the capture finishes.
- A Word, Sheet or Project tab returning while an older request is still running waits for a read asked after the return, and a read that never answers is asked again while the page says it is checking access.
- While a slow return check is pending, a Project draft takes no typing and Word and Sheet take no pointer or accessibility access, with the cursor and selection kept. Typing into Word or Sheet during the check is saved if the check confirms Edit. If Edit is lost instead, it is dropped and the draft stored when the tab went hidden, or at the return, stands, so a key pressed on a blank screen cannot replace it.
- A person reduced to Read or Comment on a Project keeps the draft sealed and is offered nothing, in the tab where it was typed as well; the Source recovery draft field is gone.
- A sign-out confirmation that follows a refused one stores both.
- A newer sign-out confirmation is no longer lost when an older one finishes moving to storage during a sign-in.
- A Project tab returning during its first load no longer takes that load's answer as the answer to its return. The load is cancelled and a new read decides.

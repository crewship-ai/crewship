- **The docs no longer promise that only the lead can change `CREW.md` (#4911).** The memory tools enforce it for `memory.write`: only the lead's sidecar can write the crew tier, so a non-lead's write is refused. Crew members share one container and one user, so a file or shell tool can still edit `/crew/shared/.memory/CREW.md` directly; "only the lead writes" is a convention, and the memory guide now says so. The memory harness reports such a write by a non-lead as a visible expected failure instead of a pass, and fails if a normal run executes fewer checks than the suite defines.

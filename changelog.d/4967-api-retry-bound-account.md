- **Retire retries within an API invocation after an observed account change.** The client stops that invocation before a retry or its own authentication-expiry signal, including account ABA; workspace-only changes keep global requests working. Appearance preference queues also retain pending writes per account/server, retire old timers, and leave unknown legacy queues inert. Activating an account does not upload the browser's existing look as a new choice; later changes merge only changed fields with that account's remote or pending values. Paused responses cannot overwrite a newer queue, and sync toggles retain pending writes in memory when queue storage is blocked. Choices made while sync was off or its initial read was pending are display-only unless already queued; the account's existing remote fields still win at activation. This covers the observed client binding and the appearance caller; other callers that initiate fresh requests, cross-tab/shared refresh ownership, refresh-cookie policy, cookie changes before binding, response-body privacy and already committed requests remain outside this guarantee.

- **`crewship apply` planned an update for every skill, even when nothing had changed.** A steady-state apply never reported "no changes" for skills, so the plan could not show drift. An existing skill with an inline or `path:` body now plans as unchanged (`=`) and is not re-imported when the stored skill already holds what the import would write. The CLI derives those values with the importer's own code and compares them with `GET /skills/{id}`. A changed body still plans an update. A `source:` URL, an unreadable stored skill or an older server also keep the update. In a combined manifest, an existing skill now plans as an update (`~`) instead of a create (`+`). No migration (#5334).

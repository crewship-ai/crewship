- **A backup of a damaged database no longer earns "contents checked" or a passing test restore.** An instance bundle's database could carry a broken CHECK constraint or a damaged index page and still pass the checksum and row counts. Create now runs SQLite's `integrity_check` and `foreign_key_check` on its private in-memory copy after writes are released, records the result in the manifest (`contents.instance.database_check`, names and rowids only, never values) and lists a `database_damaged` (or, when the check could not finish, `database_unchecked`) gap. The bundle is kept. `backup check` and the test restore repeat the check on the extracted copy and refuse proof level 2 or a passing drill; a bundle made before this check reads as unverified, not healthy.

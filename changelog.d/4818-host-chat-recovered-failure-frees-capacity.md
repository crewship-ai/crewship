- **A chat turn whose protected run later turns out to have failed now ends as failed and frees its execution slot (#4818).** When the chat stopped waiting before the agent's process exited (for example while the agent waited on a human credential request), the turn was parked until its captured output arrived. A captured successful exit completed it, but a captured failure left it parked indefinitely, holding a slot of the server's chat capacity. After enough such turns every new chat was refused with "chat execution capacity unavailable". Such a turn now settles as failed, the same way a failure observed live does. Background work keeps its reconciliation hold. Turns already parked before this fix are not released automatically; an owner can resolve them with `crewship work resolve <id> --to failed`.

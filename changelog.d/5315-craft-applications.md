- **Word and Sheet run inside Crewship.** The document engine runs in the server as WebAssembly (no extra process, same package on Linux, macOS and Windows, amd64 and arm64) and the editor is served by Crewship. The applications are not part of the binary: each release trusts one package of each, published with the release. When an instance administrator turns Word or Sheet on in Admin › Artifacts › Applications or with `crewship admin instance applications enable`, Crewship downloads it, verifies every file against the pin in the signed binary and starts it without a restart; offline, `crewship admin instance applications install sheet --file …` installs the same package. Word, Sheet and agents in them all start off. Turning an application off never deletes or changes a document: reading and export keep working, open editors may finish saving during a drain, and nobody can create or start editing. Native development profiles set by `CREWSHIP_CRAFT_NATIVE_*` keep working and show as fixed by the server configuration.
- **Word and Sheet packages carry their inventory.** Each package lists every Rust crate it is built from in a CycloneDX SBOM, and the build refuses a crate whose license is not on the permissive allowlist. Pins set with `CREWSHIP_CRAFT_COMPONENT_PINS` replace the release's pins, are logged at every start and show as a development override in Admin and the CLI.

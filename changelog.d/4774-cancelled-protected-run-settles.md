- **Stopping a protected agent run in a shared crew container now ends the run and frees the agent (#4774).** A cancelled run could only settle once the whole container was gone, which never happens for a long-lived crew container, so the run stayed open and every later message to that agent was refused with "chat execution capacity unavailable". The stop now freezes and kills the run's whole process tree: its session and every descendant, including commands that moved to their own session (as Claude Code's shell commands do) and processes whose main thread already exited. It confirms each one gone and records that, through the helper's exit status, for the exact execution; the run then settles as cancelled. Without that confirmation (an older sidecar, a process that could not be confirmed dead, or any forced end other than a cancellation) the run keeps waiting as before. A process that was already orphaned before the stop (for example a double-forked daemon whose parent exited) is no longer part of the tree and is not covered, exactly as after a normal exit.

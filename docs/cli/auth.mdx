# crewship auth

Self-service account commands. Login, logout, and whoami stay top-level
(`crewship login` / `logout` / `whoami`); `auth` hosts the newer account
mutations.

```bash
crewship auth <subcommand>
```

**Auth:** requires `crewship login`.

## Subcommands

| Command | Purpose |
| --- | --- |
| `auth passwd` | Change your own account password. |
| `auth avatar` | Upload or clear your profile picture. |
| `auth profile` | Update your display name. |

| `auth pair` | Issue a device-code so another CLI can log in without a browser. |

## `auth passwd`

Change your password. Interactively it prompts (no echo) for the current
password, then the new password twice. The new password must be at least
8 characters.

Passwords are **never** passed as flags — that would leak them into shell
history and process listings. For scripting, pipe two lines on stdin: the
current password first, the new password second.

Changing your password **signs out your other active sessions** — the
session you run this from stays logged in. It calls
[`POST /api/v1/users/me/password`](/api-reference/auth#post-/api/v1/users/me/password).

Wrong current-password guesses count against the **same account lockout as
sign-in**, and the route sits on the strict per-IP auth bucket (a CLI token
does not exempt it). Enough consecutive misses and the command fails with
`API error (423): too many failed attempts…` until the lockout window
expires — an admin can clear it with `crewship admin reset-password`.

```bash
# Interactive (recommended) — prompts for current + new, no echo:
crewship auth passwd

# Non-interactive (CI/scripts) — current on line 1, new on line 2:
printf '%s\n%s\n' "$OLD_PW" "$NEW_PW" | crewship auth passwd
```

## `auth avatar`

Upload a new profile picture, or clear it back to initials. The image must
be a **PNG, JPEG, or WebP** no larger than **2 MB**; it's served from an
authenticated endpoint so other members see it on the roster and in chat.
Backed by [`POST`/`DELETE /api/v1/users/me/avatar`](/api-reference/auth#post-/api/v1/users/me/avatar).

```bash
# Upload or replace:
crewship auth avatar ./me.png

# Remove, back to initials:
crewship auth avatar --clear
```

## `auth profile`

Update your display name. `--full-name` is the only editable field — the
API accepts nothing else on this endpoint, so there is no `--email` flag
here to promise something the server would silently ignore. Backed by
[`PATCH /api/v1/users/me`](/api-reference/auth#patch-/api/v1/users/me).

Prints the updated profile and honors the global `--format` flag (table
by default, or `json`/`yaml`/`ndjson` for scripts).

```bash
crewship auth profile --full-name "Jane Doe"
```

Editing your display name is also available in the web UI (Settings →
Profile).

<Note>
Editing your display name is available in the web UI (Settings → Profile),
backed by [`PATCH /api/v1/users/me`](/api-reference/auth#patch-/api/v1/users/me).
A CLI verb for it may follow.
</Note>

## `auth pair`

Issue a device-code pairing code, and by default wait for it to be
redeemed. This is the ISSUING side of the pairing flow — the counterpart
to `crewship login --pair --code=…` ([`crewship login`](/cli/login)),
which REDEEMS a code. Backed by
[`POST /api/v1/auth/pair/start`](/api-reference/auth#post-/api/v1/auth/pair/start)
and
[`GET /api/v1/auth/pair/poll`](/api-reference/auth#get-/api/v1/auth/pair/poll).

Run it on a CLI that is already logged in, then paste the printed snippet
on the second machine — no browser required on either side:

```bash
# Issue a code and wait (default) for it to be redeemed:
crewship auth pair

# Issue a code and return immediately, without waiting:
crewship auth pair --no-wait

# Tag the issuing side with an adapter hint (telemetry only):
crewship auth pair --adapter CLAUDE_CODE

# Tune how long / how often to poll while waiting:
crewship auth pair --timeout 5m --poll-interval 3s
```

| Flag | Default | Purpose |
| --- | --- | --- |
| `--adapter` | _(none)_ | Adapter hint recorded with the code (`CLAUDE_CODE`, `GEMINI_CLI`, `CODEX_CLI`, `OPENCODE`, `CURSOR_CLI`, `FACTORY_DROID`). Telemetry only — the server never routes on it. |
| `--no-wait` | `false` | Print the code and exit immediately, without polling for redemption. |
| `--timeout` | `9m` | How long to wait for the code to be redeemed. Codes expire after 10 minutes server-side, so the default leaves a margin. |
| `--poll-interval` | `2s` | How often to poll `GET /api/v1/auth/pair/poll` while waiting. |

<Warning>
The code **is** the credential for the redeeming side — `POST
/api/v1/auth/pair/redeem` is intentionally unauthenticated, so anyone who
has the code can log in as you within its 10-minute window. Treat it like
a password: read it over a channel you trust, and let an unused code
expire rather than posting it anywhere public.
</Warning>

Without `--no-wait`, the command polls until the code is redeemed
(`status: consumed`, exit `0`), expires before anyone redeemed it (`status:
expired`, non-zero exit), or the `--timeout` budget runs out while it is
still pending (also non-zero exit — a timeout is never reported as
success). `--format json` reports `code`, `expires_at`, `status`, `paired`,
and `waited`, so a script can branch on `status` without parsing prose.

# crewship doc

Work with opt-in collaborative Docs on an existing human-owned Page. The current
CLI profile supplies the workspace and exact human bearer. Page ACLs apply;
scoped tokens need `pages:read` for reads and `pages:write` for mutations.
`pages:*` grants both. These commands do not mint agent authority.

Mutation JSON uses the confirmed source schema (`1`, `2` or `3`) and original `page_id` (required for3), a stable unique `id`, and (except initialize) the
opaque `epoch` returned by a fresh read. A transport retry reuses the exact ID
and payload. A conflict requires rereading and human review; the CLI does not
silently rebase. JSON input is one object, at most 2 MiB. See the
[API contracts](/api-reference/documents) for every field.

## crewship doc status

`crewship doc status` checks `GET /api/v1/documents/status`. The `enabled` response
reports server configuration; it does not certify a container image or model.

## crewship doc read

`crewship doc read report` reads `GET /api/v1/pages/{slug}/document`: confirmed
revision, opaque epoch, binary snapshot/replay, JSON content, semantic outline
and current permission flags.

`--block ID` requests one current paragraph, heading or code block instead of the
whole read envelope. It preserves the original Page/schema/revision/epoch and
block hash; text is complete up to 256 KiB UTF8, never a truncated summary. Missing
blocks return 404, unsupported or oversized blocks return 422, changed sources
return 409, and a full managed envelope exceeding 4 MiB returns 502. No automatic
retry, history lookup or fresh-base substitution occurs. Example:

```bash
crewship doc read report --block introduction
```

## crewship doc outline

`crewship doc outline report` calls the same read endpoint and prints only its
outline: actual block IDs, parents, types, text and hashes.

## crewship doc initialize

`crewship doc initialize report --file initialize.json` calls
`POST /api/v1/pages/{slug}/document/initialize`. `--file` names a JSON file;
`--file -` reads stdin. Body: `{id,schema,page_id,body:<schema-valid document tree>}`.
Only an empty Page owned by the authenticated human may attach a Doc.

## crewship doc patch

`crewship doc patch report --file patch.json` calls
`POST /api/v1/pages/{slug}/document/patch`. `--file` names a JSON file;
`--file -` reads stdin. Semantic body:
`{id,schema,page_id,epoch,target,text,ifRev,ifHash}`. Use the block ID/hash and revision
from the outline. Raw editor updates use `{id,schema,page_id,epoch,kind:"human",update}`;
agents cannot submit raw CRDT updates.

## crewship doc checkpoint

`crewship doc checkpoint report --file checkpoint.json` calls
`POST /api/v1/pages/{slug}/document/checkpoint`. `--file` names a JSON file;
`--file -` reads stdin. Body: `{id,schema,page_id,epoch,ifRev}`. Success pins a complete,
confirmed state; it does not infer success from local editor content.

## crewship doc checkpoints

`crewship doc checkpoints report` calls
`GET /api/v1/pages/{slug}/document/checkpoints` and lists up to 1000 retained checkpoints.

## crewship doc checkpoint-read

`crewship doc checkpoint-read report checkpoint-id` calls
`GET /api/v1/pages/{slug}/document/checkpoints/{checkpoint}` to inspect the pinned
content and outline without replacing the live document.

## crewship doc upgrade

`crewship doc upgrade report --file upgrade.json` calls
`POST /api/v1/pages/{slug}/document/upgrade`. `--file` names one JSON file;
`--file -` reads stdin. Body: `{id,schema:1|2,target_schema:3,page_id,epoch,ifRev}`.
Only a human with live write access can explicitly enable links/code. Freeze
all original fields; uncertain acknowledgment retries exactly. No read upgrades,
no automatic rebase, and no agent raw writes or human-profile fallback.

## crewship doc restore

`crewship doc restore report --file restore.json` calls
`POST /api/v1/pages/{slug}/document/restore`. `--file` names a JSON file;
`--file -` reads stdin. Body: `{id,schema,page_id,epoch,ifRev,checkpoint}`. Restore advances
history generation, fences stale tabs and keeps the same Page and grants.

## crewship doc export

`crewship doc export report > report.md` calls
`GET /api/v1/pages/{slug}/document/export` and writes Markdown of confirmed
content. This command emits text rather than the usual JSON response envelope.

## crewship doc comments

`crewship doc comments report` calls
`GET /api/v1/pages/{slug}/document/comments`. Anchor status is `attached`,
`collapsed`, `detached` or `resolved`; detached text is never silently reattached.

## crewship doc comment

`crewship doc comment report --file comment.json` calls
`POST /api/v1/pages/{slug}/document/comments`. `--file` names a JSON file;
`--file -` reads stdin. Body:
`{id,schema,page_id,epoch,ifRev,block,from,to,text}`. Offsets select text within one
paragraph or heading. A comment does not dispatch an agent.

## crewship doc comment-resolve

`crewship doc comment-resolve report --file resolve.json` calls
`POST /api/v1/pages/{slug}/document/comments/resolve`. `--file` names a JSON file;
`--file -` reads stdin. Body:
`{id,schema,page_id,epoch,ifRev,comment,version,resolved}`. `resolved:false` reopens the
same comment; resolution requires current Page write access.

## crewship doc request

`crewship doc request report --file request.json` calls
`POST /api/v1/pages/{slug}/document/requests`. `--file` names a JSON file;
`--file -` reads stdin. Body:
`{page_id,chat_id,instruction,base_rev,submission_id,targets:[{id,hash,from,to,quote}]}`.
`page_id` is the existing Page ID. Capture `base_rev` and each full block hash
from confirmed state; targets preserve the exact selected quotation and its
UTF-16 offsets within one paragraph or heading. Supply exactly one target with at most
4096 UTF-16 code units of quoted text in total. A nonempty quote must match the
specified range exactly. A changed revision, block hash or selection returns
`409`; the CLI does not fetch replacement state, retry or rebase automatically.
Discard a stale draft and explicitly select again. Exact transport retries retain
the entire body and submission ID, including the original base and targets.
The selected private chat must belong to this human, and its agent needs an
explicit Page write grant. A `202` response means queued work, not completion.
Success requires the admitted agent's one durable semantic patch against the
original selected baseline and its exact resulting checkpoint. This does not
claim multi-block or multiple-patch completion.

For separate schema3 whole-block structural authorization, replace `targets`
with `structure:{block_ids:["root-id",...],allow_insert_after:true}`. IDs must
be an ordered contiguous range of at most256 root blocks. The server captures
canonical subtree hashes and surrounding boundaries at the original revision;
the human does not provide internal proof. **Select all blocks** is explicit
and unavailable above256, with no truncation. This permits one atomic insert/
delete/reorder batch inside the selected structural scope. Existing text grants
remain text-only. Moves with comment anchors are refused; deletion retains
detached threads. Schema1/2 need an explicit human upgrade before this mode.

## crewship doc agent

These protected commands use only the original run's `CREWSHIP_AGENT_TOKEN`
and fixed sidecar transport. They never load a human profile or accept server/
workspace overrides. They require an admitted structural request.

## crewship doc agent read

`crewship doc agent read report` returns current text/outline plus the original
server-owned request context, excluding binary Yjs snapshot/update bytes.
Reading a newer head never authorizes rebasing.

## crewship doc agent apply

`crewship doc agent apply report --operations-file operations.json` accepts only
a JSON **array** of1..256 operations, at most256KiB (or stdin with `-`):

```json
[{"op":"insert_after","after_id":"selected-root","node":{"type":"paragraph","content":[{"type":"text","text":"New paragraph"}]}}]
```

Other operations are `{op:"delete",id}` and `{op:"move_before",id,before_id}`.
Inserted nodes are plain paragraph, heading with level1..3, or codeBlock, without
caller IDs/marks. The tool supplies original Page/schema/request/revision and
computes hashes. Model input cannot override those values. The batch is atomic;
failure publishes no partial update. Repeat unchanged operations after uncertain
acknowledgement, including after transport epoch renewal, to recover the original
receipt. A changed human revision without an existing receipt conflicts.

## crewship doc agent checkpoint

`crewship doc agent checkpoint report` takes no JSON envelope. It checkpoints
only the original request's successful single patch at original base+1; no patch
or an intervening edit conflicts. Report success after both durable receipts.
MCP equivalents `doc_read`, `doc_apply` and `doc_checkpoint` use the same protected
adapter, with `{slug}`, `{slug,operations}` and `{slug}` respectively. MCP HTTP
results are bounded to1MiB; larger reads use the protected CLI/HTTP adapter.

## crewship doc request-list

`crewship doc request-list report` calls
`GET /api/v1/pages/{slug}/document/requests` for current request/result cards and
eligible private agent chats. Results stay on the same Page.

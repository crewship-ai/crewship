# crewship memory

Access memory FTS5 indexes on the local filesystem without a running server. Useful for development, debugging, and scripting.

## Subcommands

### search

FTS5 search across memory with scope control.

```bash
crewship memory search <query> [flags]
```

**Flags:**

| Flag | Short | Default | Description |
|------|-------|---------|-------------|
| `--path` | `-p` | (required) | Base path (meaning depends on scope) |
| `--scope` | `-S` | `agent` | `agent`, `crew`, `workspace`, or `all` |
| `--limit` | `-l` | `10` | Maximum results per scope |
| `--output-format` | `-F` | — | **Deprecated.** Alias for the global `--format`/`-f`. |

<Warning>
  `memory search` used to own a **local** `--format` flag with the `-F`
  shorthand. Because it took the name `format`, it shadowed the global
  persistent flag on this command — and a shadowed persistent flag takes its
  shorthand with it, so `crewship memory search … -f json` did not fall back to
  human output, it **failed** with `unknown shorthand flag: 'f'`.

  The global `--format`/`-f` now reaches this command like every other, with the
  full `table|json|yaml|ndjson|quiet` vocabulary instead of `table|json`. `-F`
  survives as a deprecated alias under the name `--output-format` so existing
  scripts keep working; it prints a deprecation notice and will be removed.
</Warning>

**Examples:**

```bash
# Search agent memory
crewship memory search "PostgreSQL" -p /path/to/agents/lead/.memory

# Search crew shared memory
crewship memory search "deployment" -p /path/to/crew-root -S crew

# Search both scopes, JSON output
crewship memory search "database" -p /path/to/agents/lead -S all -F json

# Search workspace memory
crewship memory search "budget" -p ~/.crewship/memory/ws-123 -S workspace
```

### status

Show memory index statistics.

```bash
crewship memory status [flags]
```

**Example:**

```bash
crewship memory status -p /path/to/agents/lead/.memory
# [agent] /path/to/agents/lead/.memory
#   Files:   3
#   Chunks:  12
#   Size:    48 KB
#   Indexed: 2026-04-14T10:15:52Z
#   Ready:   true
```

**Exit codes.** A scope whose index cannot be read is reported on stderr, naming the resolved path (which `--path` *and* `--scope` decide together) and the cause — the directory does not exist, is not a directory, cannot be entered, or holds an `index.sqlite` that cannot be opened. When **every** scope fails the command exits `3`; a partial failure exits `0` with the successful scopes on stdout. SQLite's own `unable to open database file (14)` is never what you see: that string is identical for all four causes and names none of them.

When the base path itself is missing, that is a mistyped `--path` and the message says so:

```bash
crewship memory status -p /path/that/is/not/there
# [agent] /path/that/is/not/there/.memory does not exist, and neither does /path/that/is/not/there — check --path and --scope (…)
# no readable memory index for scope "agent" under /path/that/is/not/there
# exit 3
```

When the base path is real and has simply never been indexed, [`reindex`](#reindex) is the fix and it creates the directory itself:

```bash
crewship memory status -p /path/to/crews/abc123
# [agent] /path/to/crews/abc123/.memory does not exist — build the index with `crewship memory reindex`, which creates it, or check --path and --scope (…)
# exit 3
crewship memory reindex -p /path/to/crews/abc123
# [agent] reindexed 0 files (0 chunks) in 19ms
# exit 0
```

A directory you cannot enter is called out as such, because inside an agent container the memory tree belongs to uid 1001:

```bash
crewship memory status -p /crew/agents/lead
# [agent] /crew/agents/lead/.memory cannot be read: permission denied — you are uid 1000, and memory dirs written inside an agent container are owned by uid 1001
# exit 3
```

### health

Print the 5-metric memory health score for the caller's workspace. Hits the running server (requires `crewship login` and a workspace context) — unlike `search`/`status`/`reindex` which read local FTS indexes, `health` calls `GET /api/v1/memory/health`, which **recomputes fresh** on every request from five aggregate SQL queries. The persisted `memory_health_snapshots` table is for trend graphs, not for this command.

```bash
crewship memory health [--crew <slug-or-id>]
```

**Flags:**

| Flag | Description |
|------|-------------|
| `--crew` | Scope to a single crew by slug or ID. Omit for workspace-aggregate. |

The global `--format` flag is honoured (`table`, `json`, `yaml`, `ndjson`).

**Example:**

```bash
crewship memory health
# Memory health (workspace-wide): 77/100
#
#   freshness        83.1
#   coverage         62.0
#   coherence        80.2
#   efficiency       77.4
#   reachability     78.0
```

The `77/100` is colour-coded — red below 50, yellow 50–74, green 75 and above. The colour is applied via terminal escape codes; in pipes (`| cat` or `--format json`) it disappears. See [Episodic memory — health scoring](/guides/episodic-memory#health-scoring) for what each metric measures and the weighted-composite formula.

### reindex

Rebuild FTS5 index from markdown files. Signal-aware (responds to SIGINT/SIGTERM).

```bash
crewship memory reindex [flags]
```

**Example:**

```bash
crewship memory reindex -p /path/to/crew-root -S crew
# [crew] reindexed 3 files (10 chunks) in 19ms
```

**It creates the index directory it is asked to build in**, so the `.memory` a crew has never had is one `reindex` away rather than a `mkdir` you have to work out. It will not create the *base* path: a `--path` whose own directory is absent is a typo, and inventing the tree would hide it.

Creating `.memory` needs the base path to exist **and be writable by you**. When it is not, `reindex` says so rather than reporting the directory as merely missing — that wording advises running `reindex`, which is the command that just failed:

```bash
crewship memory reindex --path /crew/read-only
# [agent] /crew/read-only/.memory cannot be created: permission denied — /crew/read-only
#   is not writable by uid 1000, so `crewship memory reindex` has nowhere to build the
#   index (memory written inside an agent container is owned by uid 1001)
```

Returns a non-zero exit code if all reindex operations fail — `3` when the reason is that no scope had a directory to index, which is the code `status` uses for the same condition, and `1` otherwise. Per-scope failures go to stderr with the same actionable wording `status` uses.

### hybrid

Search workspace memory **through the server's hybrid engine** — full-text chunks plus episodic journal recall, merged and ranked. Unlike `search` (local filesystem FTS), this requires a login token and works from any machine.

```bash
crewship memory hybrid "deploy runbook"
crewship memory hybrid "API key rotation" --limit 5 --scope crew_shared --crew backend
```

| Flag | Default | Description |
|------|---------|-------------|
| `--limit` | `10` | Maximum hits. |
| `--scope` | _(all visible)_ | `own` (agent-only) or `crew_shared` (crew-bound). |
| `--crew` | | Crew slug or id for `crew_shared` scope. |

### versions (server API)

The `memory versions` group mirrors `log`/`show`/`restore` **over the running server's API** — use these from any machine; the direct-DB commands below only work on the server host. The workspace comes from the auth context.

```bash
crewship memory versions list "crew:<crew_id>/learned-x.md" --limit 20
crewship memory versions show "crew:<crew_id>/learned-x.md" <sha> > recovered.md
crewship memory versions restore "crew:<crew_id>/learned-x.md" <sha> <canonical-path> --tier learned
```

`restore` requires OWNER/ADMIN, prompts for confirmation (`--yes` skips), and the server confines `<canonical-path>` to its configured memory root.

`list` columns: `SHA256`, `WRITTEN`, `BYTES`, `WRITTEN BY`. `--limit` defaults to 20 and the server clamps it to 1–1000.

#### Projection state — "nothing here" vs "we could not look"

`list` leads with a **projection state** whenever it changes how the list should be read. An empty version history has two completely different meanings and they used to print the same empty table:

| State | Meaning | How to read an empty list |
|---|---|---|
| `recorded` | A writer records this path into the audit chain. | Nothing has been written to it yet. This is a fact. |
| `unrecorded` | No writer records this path. | Says nothing about what is on disk — the file may have changed a hundred times. |
| `unavailable` | The server has no blob root configured, so no write of any tier is recorded. | Same as `unrecorded`, different cause. |

Recorded paths are `agent:<slug>/…` or `crew:<crew_id>/…` ending in `AGENT.md`, `CREW.md`, `pins.md`, `learned-*.md`, or `daily/*.md`. Everything else — `lessons.md`, `PERSONA.md`, `peers/*` — is `unrecorded` and has its own history surface; the `reason` text names it.

The state and its `reason` are printed above the table in human output and carried verbatim in `--format json`:

```bash
crewship memory versions list "agent:martin/lessons.md" --format json | jq .projection
# { "state": "unrecorded", "reason": "Lessons are written by consolidate.WriteLesson, ..." }
```

<Note>
A server predating this field answers without it. The CLI reads that as `recorded` — the state every path had when the only writers were recording ones — so an older server is never reported as having versioning switched off.
</Note>

### log

List the `memory_versions` audit chain for a path, newest-first. **Reads the server** the CLI targets, via `GET /api/v1/admin/memory/versions` (ADMIN+).

```bash
crewship memory log <workspace-id> <path>
crewship memory log <workspace-id> <path> --limit 100 --format text
crewship memory log <workspace-id> <path> --local     # the database file on this host
```

<Note>
Until [#2086](https://github.com/crewship-ai/crewship/issues/2086) this
command opened `~/.crewship/crewship.db` directly and ignored `--server` /
`CREWSHIP_SERVER` / `--profile` — while the route above already existed and
had no CLI command at all. On any host where `crewshipd` runs with its own
`DATABASE_URL` (every development clone uses `file:./crewship.db`) it
therefore reported an audit chain that was not the one being audited.

`--local` is the old behaviour, asked for explicitly: it reads the database
file on this host, works with the server down, and prints the path it opened.
It is also the only path that reports `payload_ref` — the API deliberately
does not hand out on-disk blob locations.
</Note>

`<path>` is the audit-trail identifier the consolidator + approve flow record under. For canonical learned files this is `crew:<crew_id>/learned-YYYY-MM-DD.md` (see `internal/consolidate.canonicalAuditPath`); for pins it's `crew:<crew_id>/pins.md`.

| Flag | Default | Description |
|---|---|---|
| `--limit <n>` | `20` | Max rows. Clamped to `1000` on the `--local` path by the local query. |
| `--format` | `json` | `json` (pretty-printed) or `text` (one row per line, git-log–style: `<sha-12>  <ts>  <bytes> B  <writtenBy>`). Always on stdout; the "which database" note is on stderr, so `--format json \| jq` is unaffected. |
| `--local` | `false` | Read the database file on this host instead of the server. |

Empty result prints `no versions for <ws> @ <path>` to stderr and exits 0.

<Note>
**Partial results on a very busy workspace.** The route filters by path
*prefix* while this command wants one *exact* path, and rows come back ordered
by `(written_at, id)` across the whole workspace rather than per path. So a
rarely-written file can sit behind a long run of unrelated versions. The CLI
walks at most 200 pages of 500 rows; if it stops there it prints the matches it
found and warns on stderr:

```
warning: stopped after 200 pages of /api/v1/admin/memory/versions without
exhausting the prefix "crew:c1/notes.md", so this answer is partial …
```

Exit code stays `0` and stdout still carries only rows, so `--format json | jq`
is unaffected — check stderr before treating a short list as the whole chain.
`--local` has no ceiling: it queries the file directly.
</Note>

### show

Print the raw content of one historical version to stdout. The canonical file on disk is **not** touched — this is the "preview without restoring" path.

```bash
crewship memory show <workspace-id> <path> <sha>
crewship memory show <ws> <path> <sha> > preview.md
crewship memory show <ws> <path> <sha> --local   # the database file on this host
```

Reads the server the CLI targets: the row is resolved by `(path, sha)` through
`GET /api/v1/admin/memory/versions`, then its bytes are streamed from
`GET /api/v1/admin/memory/versions/{id}/content`. Two calls because the content
route is keyed by row id while the arguments here are the audit chain's own
coordinates — which is what `memory log` puts in front of you.

`--local` reads the database file and blob store on this host instead.

| Flag | Default | Description |
|---|---|---|
| `--local` | `false` | Read the database file and blob store on this host instead of the server. |

Stdout = raw blob bytes (pipe-friendly). Stderr carries status/errors. Exit codes:

- `0` — blob found and streamed
- `1` — version not found or read error
- `2` — invalid usage

A sha that is not in the chain always runs the resolving walk to its end, so on
a very busy workspace it can hit the 200-page ceiling described under
[`log`](#log). That is still `1` / `version not found` — the ceiling's stderr
warning prints first, so a not-found that might be a truncation artefact says
so rather than masquerading as a different error.

### restore

Atomically replace the canonical memory file at `<canonical-path>` with the content of version `<sha>`, then write a fresh `memory_versions` row so the chain stays forward-only — history is never rewritten.

```bash
crewship memory restore <workspace-id> <path> <sha> <canonical-path> --local
crewship memory restore ws_a crew:abc/learned-2026-05-20.md <sha> /data/memory/ws_a/crew_abc/learned-2026-05-20.md \
  --user operator@example.com --tier learned --local
```

This one has no server-side route and is not getting one: it writes a
canonical file onto **this machine's** disk from a blob in **this machine's**
content-addressed store, so there is nothing a remote server could do with the
request. When `--server` / `CREWSHIP_SERVER` / `--profile` names a server it
refuses rather than restore from another instance's history; `--local` is how
you say you mean this host.

| Flag | Default | Description |
|---|---|---|
| `--blob-root` | `{CREWSHIP_DATA_DIR}/memory/versions` (or `~/.crewship/memory/versions`) | Content-addressed blob store root. Match what the server wrote to. |
| `--user` | `$USER` (falls back to `cli`) | `writtenBy` for the new audit row. Use a real operator id for compliance trails. |
| `--tier` | `learned` | Tier label for the new audit row: `agent` / `crew` / `workspace` / `pins` / `learned`. |
| `--force` | `false` | Skip the "canonical path must stay inside the data dir" guard. Use only when a workspace's memory dir lives outside the standard tree. |
| `--local` | `false` | Required when the CLI names a server: this command only ever acts on the database file and blob store on this host. |

The path guard rejects empty strings, any path containing `..`, and any target whose absolute form does not start with `{blob-root}/..` (the data dir, one level above `versions`).

### export

Write memory out as a portable OKF bundle — markdown with YAML frontmatter, readable and git-friendly. Goes through the server, so it works from any machine the CLI can reach.

```bash
crewship memory export --crew engineering --agent alex --out ./alex-memory
crewship memory export --crew engineering --out ./crew-memory
```

| Flag | Default | Description |
|---|---|---|
| `--out` | — | Destination directory for the bundle. Required. |
| `--crew` | — | Crew slug or id. Required. |
| `--agent` | — | Agent slug. Omit for the crew-shared tier. |

OWNER/ADMIN only — the bundle contains every private note the agent holds.

The same export is available in the dashboard: an agent's **Memory** tab has an **Export** button that downloads the bundle. Import has no UI equivalent — see [Memory Portability](/guides/memory-portability).

### import

Read a memory directory produced by another harness, map it onto Crewship's tiers, and write it in. Recognises `crewship`, `okf`, `nanoclaw` and `openclaw` layouts.

```bash
# Preview — no login needed, nothing written
crewship memory import --from ~/.openclaw/workspace-main --crew engineering --agent alex --operator pavel

# Write it
crewship memory import --from ./nanoclaw --group telegram_dev-team --crew eng --agent alex --apply
```

| Flag | Default | Description |
|---|---|---|
| `--from` | — | Source memory directory. Required. |
| `--crew` | — | Target crew slug or id. Required. |
| `--agent` | — | Target agent slug. Omit for the crew-shared tier. |
| `--format` | `auto` | `auto` / `crewship` / `okf` / `nanoclaw` / `openclaw`. |
| `--operator` | — | Slug of the person an operator card (OpenClaw `USER.md`) belongs to. Without it the card is skipped. |
| `--group` | — | Which NanoClaw group to import when the source holds several. Required in that case. |
| `--with-crew` | `false` | Also write crew-shared documents. Every agent in the crew reads them. |
| `--apply` | `false` | Actually write. Without it the command prints the plan and exits. |

`--apply` requires OWNER/ADMIN, the same as `export` — it writes into the context an agent reasons from.

Imported documents pass through the same guards an agent's own writes do: a closed allowlist of paths, per-file size ceilings, secret and prompt-injection scanning, and symlink-safe confinement. Refusals are listed per document and the command exits non-zero; a failed document does not stop the rest. Full mapping table and limits: [Memory Portability](/guides/memory-portability).

## Scope and Path Resolution

The meaning of `--path` depends on the selected scope:

| Scope | `--path` should point to |
|-------|--------------------------|
| `agent` | Agent `.memory/` dir or agent dir (auto-appends `.memory/`) |
| `crew` | Crew root dir (resolves to `<path>/shared/.memory/`) |
| `workspace` | Workspace memory dir (e.g. `~/.crewship/memory/<workspace-id>`) |
| `all` | Crew root dir (searches agent + crew) |

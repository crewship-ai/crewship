# crewship integration

Manage MCP server integrations at workspace scope, crew scope, and through
agent bindings. The alias is `intg`.

```bash
crewship integration <subcommand> [flags]
crewship intg <subcommand> [flags]
```

Every integration command requires `crewship login` and an active workspace.
Arguments named `id-or-name` accept either the integration ID or its name;
crew and agent arguments accept slugs (and the Composio agent commands also
accept agent IDs).

All commands also inherit the global `--server`/`-s`, `--workspace`/`-w`,
`--profile`, `--format`/`-f`, `--verbose`/`-v`, `--no-color`, and
`--server-allow-mismatch` flags. `--format` defaults to `table`; it is honored
by commands that use the formatter, while commands whose output is explicitly
described as text or JSON below keep that output shape.

## Command reference

### Workspace scope

| Command | Human output | Structured output |
| --- | --- | --- |
| `integration list` | Table: `NAME`, `DISPLAY`, `TRANSPORT`, `ENDPOINT`, `ENABLED`, `AGENTS`, `CREWS`. Long endpoints are shortened. | The API list. |
| `integration add` | `Integration created: <name> (<id>)` | No structured output; the success line is always printed. |
| `integration get <id-or-name>` | Detail fields: ID, name, display, transport, endpoint, command, enabled, icon, created, updated. Empty optional fields show `-`. | The integration object. |
| `integration remove <id-or-name>` | Confirmation prompt, then `Integration <arg> deleted.` | No structured output. |
| `integration enable <id-or-name>` | `Integration <arg> enabled.` | No structured output. |
| `integration disable <id-or-name>` | `Integration <arg> disabled.` | No structured output. |
| `integration test <id-or-name>` | The server result is printed as JSON. | The server result object. |
| `integration crews-overview` | The server result is printed as JSON. | The server result array. |

`remove` accepts `-y`/`--yes` to skip its confirmation prompt. `add` requires
`--name`; `--display` defaults to the name, and `--transport` defaults to
`streamable-http`. For `stdio`, `--command` is split into an executable and
arguments before it is sent to the server; no shell is run.

### Agent bindings

| Command | Human output | Structured output |
| --- | --- | --- |
| `integration bind` | `Agent <agent> bound to integration <server>.` | No structured output. |
| `integration unbind` | `Binding <binding-id> removed from agent <agent>.` | No structured output. |
| `integration agent-bindings <agent-slug>` | Table: `BINDING ID`, `SERVER`, `SCOPE`, `CREDENTIAL`, `TYPE`, `ENABLED`. Missing credentials show `-`; missing types display `bearer`. | The binding list. |
| `integration resolve <agent-slug>` | Table: `NAME`, `DISPLAY`, `SCOPE`, `TRANSPORT`, `CREDENTIAL`. Missing credentials show `-`. | The resolved integration list. |
| `integration agent update-binding <agent-slug> <binding-id>` | `Binding <binding-id> on agent <agent> updated.` | No structured output. |

`bind` requires `--agent` and `--server`; `unbind` requires `--agent` and
`--binding-id`. The binding ID is the value in the `BINDING ID` column, not the
workspace integration ID.

### Crew scope

| Command | Human output | Structured output |
| --- | --- | --- |
| `integration crew list <crew-slug>` | Table: `ID`, `NAME`, `DISPLAY`, `TRANSPORT`, `ENDPOINT`, `ENABLED`. Long endpoints are shortened. | The crew integration list. |
| `integration crew create <crew-slug>` | `Crew integration created: <name> (<id>)` | No structured output. |
| `integration crew update <crew-slug> <integration-id>` | `Crew integration <id> updated.` | No structured output. |
| `integration crew delete <crew-slug> <integration-id>` | Confirmation prompt, then `Crew integration <id> deleted.` | No structured output. |
| `integration crew test <crew-slug> <integration-id>` | The server result is printed as JSON. | The server result object. |

`crew delete` accepts `-y`/`--yes`. `crew create` requires `--name`; its
`--display` and `--transport` defaults match workspace `add`. `--link-workspace-server`
links the new crew integration to a workspace integration by ID.

### Per-tool controls

These commands apply only to crew-scoped integrations.

| Command | Human output | Structured output |
| --- | --- | --- |
| `integration tools list <crew-slug> <integration-id>` | Table: `TOOL`, `ENABLED`, `DESCRIPTION`, `UPDATED`; missing descriptions show `-`, and long descriptions are shortened. | The tool-binding list. |
| `integration tools enable <crew-slug> <integration-id> <tool-name>` | `Tool <tool> on <crew>/<integration-id> enabled.` | No structured output. |
| `integration tools disable <crew-slug> <integration-id> <tool-name>` | `Tool <tool> on <crew>/<integration-id> disabled.` | No structured output. |
| `integration tools refresh <crew-slug> <integration-id>` | If the server returns an empty body: `Tool bindings refresh requested for <crew>/<integration-id>.`; otherwise the server result is printed as JSON. | The server result when it returns one. |

`tools refresh` currently sends an empty tool list. The server treats that as a
no-op; it does not perform live MCP discovery from the CLI.

### Composio managed integrations

The `integration composio` group contains `inventory`, `toolkits`,
`tools <toolkit>`, `triggers types`, `triggers active`, `triggers enable <slug>`,
`key show`, `key set`, `key remove`, `default show`, `default enable`,
`default set <user_id>`, `connect <toolkit>`, `bind <agent-slug-or-id>`,
`unbind <agent-slug-or-id>`, `bindings <agent-slug-or-id>`, and the account
commands `account revoke <account-id>`, `account refresh <account-id>`, and
`account remove <account-id>`.

Read commands (`inventory`, `toolkits`, `tools`, `triggers types`,
`triggers active`, `default show`, `key show`, and `bindings`) use human tables
or notices by default and honor `--format json`, `yaml`, or `ndjson` for the
raw API response. Mutation commands print the text shown below.

| Command | Human output / behavior |
| --- | --- |
| `composio inventory` | Connector catalog table (`TOOLKIT`, `NAME`, `STATUS`) and connected-users table (`USER_ID`, `APPS`, `ACCOUNTS`). If unconfigured, prints a configuration notice. |
| `composio toolkits` | Table `SLUG`, `NAME`, `CATEGORY`, `TOOLS`, followed by the number shown and total. |
| `composio tools <toolkit>` | Table `SLUG`, `NAME`, `DESCRIPTION`, followed by the number shown and total. |
| `composio triggers types` | Table `SLUG`, `TOOLKIT`, `TYPE`, `DESCRIPTION`, followed by the number shown and total. |
| `composio triggers active` | Table `ID`, `TRIGGER`, `USER_ID`, `STATE`. |
| `composio triggers enable <slug>` | `Trigger <slug> enabled for user "<user>" (id: <id>).` Requires `--user`. |
| `composio key show` | Prints whether the key is configured, its source, and optional label; never prints the key. |
| `composio key set` | `Composio key saved & validated (source: <source>).` Requires `--key`. |
| `composio key remove` | `Composio workspace key removed.` |
| `composio default show` | Table `FLAG`, `DEFAULT_USER`, `DEFAULT_SERVER`, `CONNECTED_USERS`; when the flag is off, also prints a note. |
| `composio default enable` | `Default Composio connector provisioned for user "<user>" (server <id>).` |
| `composio default set <user_id>` | `Default Composio connector set to user "<user>" (server <id>).` |
| `composio connect <toolkit>` | Prints an OAuth URL to open. Requires `--user`. |
| `composio bind <agent-slug-or-id>` | Prints the bound user and one indented line per provisioned app (toolkit, mode, endpoint). Requires `--user`. |
| `composio unbind <agent-slug-or-id>` | Removes one app with `--app`, or all apps when omitted, and prints the result. |
| `composio bindings <agent-slug-or-id>` | Table `TOOLKIT`, `MODE`, `USER_ID`, `ENDPOINT`; an agent with none gets a no-bindings message. |
| `composio account revoke <account-id>` | `Connected account <id> revoked.` The account row survives. |
| `composio account refresh <account-id>` | `Connected account <id> refreshed.` |
| `composio account remove <account-id>` | `Connected account <id> deleted.` |

When Composio is unconfigured, the catalog read commands print a notice and
return successfully in human mode. Set a workspace key with `key set`, or use
the server-level `COMPOSIO_API_KEY` fallback.

## Flags

### Workspace `add`

| Flag | Default | Meaning |
| --- | --- | --- |
| `--name <slug>` | empty; required by the command | Integration name. |
| `--display <string>` | empty; becomes `--name` | Display name. |
| `--transport <string>` | `streamable-http` | `streamable-http` or `stdio`. |
| `--endpoint <url>` | empty | MCP endpoint URL. |
| `--command <string>` | empty | Stdio launch line. |
| `--icon <name>` | empty | Lucide icon name. |

### Workspace `bind`

| Flag | Default | Meaning |
| --- | --- | --- |
| `--agent <slug>` | empty; required | Agent slug. |
| `--server <name>` | empty; required | Integration name. |
| `--credential <name>` | empty | Credential to bind. |
| `--cred-type <string>` | `bearer` | `bearer`, `api_key`, or `basic`. |
| `--cred-header <name>` | empty | Custom header for `api_key`. |

### Workspace `unbind`

| Flag | Default | Meaning |
| --- | --- | --- |
| `--agent <slug>` | empty; required | Agent slug. |
| `--binding-id <id>` | empty; required | Agent binding row ID. |

### Deletes

`integration remove` and `integration crew delete` each support `-y` or
`--yes`, default `false`, to skip confirmation.

### Crew `create`

| Flag | Default | Meaning |
| --- | --- | --- |
| `--name <slug>` | empty; required | Integration name. |
| `--display <string>` | empty; becomes `--name` | Display name. |
| `--transport <string>` | `streamable-http` | `streamable-http` or `stdio`. |
| `--endpoint <url>` | empty | MCP endpoint URL. |
| `--command <string>` | empty | Stdio launch line. |
| `--icon <name>` | empty | Lucide icon name. |
| `--link-workspace-server <id>` | empty | Workspace integration ID to link. |

### Crew `update`

All flags default to empty/unset except `--enabled`, whose default is `true`.
Only flags explicitly supplied are patched.

| Flag | Meaning |
| --- | --- |
| `--display <string>` | New display name. |
| `--transport <string>` | New transport: `streamable-http` or `stdio`. |
| `--endpoint <url>` | New endpoint URL. |
| `--command <string>` | New stdio launch line. |
| `--icon <name>` | New Lucide icon name. |
| `--enabled <bool>` | Set enabled state. |

### Agent `update-binding`

All string flags default to empty/unset. `--enabled` defaults to `true`; only
changed flags are sent.

| Flag | Meaning |
| --- | --- |
| `--credential <name>` | Credential name; an explicitly empty value clears it. |
| `--cred-type <string>` | Credential type: `bearer`, `api_key`, or `basic`. |
| `--cred-header <name>` | Custom header for `api_key`. |
| `--env-var-name <name>` | Environment variable name; an explicitly empty value clears it. |
| `--enabled <bool>` | Set enabled state. |

### Composio filters and options

| Command | Flag | Default |
| --- | --- | --- |
| `toolkits` | `--search`, `--category` | empty/unset |
| `toolkits` | `--limit` | `0` (server-side default) |
| `tools <toolkit>` | `--search` | empty/unset |
| `tools <toolkit>` | `--limit` | `0` (server-side default) |
| `triggers types` | `--toolkit`, `--search` | empty/unset |
| `triggers types` | `--limit` | `0` (server-side default) |
| `triggers enable <slug>` | `--user <id>` | empty; required |
| `connect <toolkit>` | `--user <id>` | empty; required |
| `key set` | `--key <ak_…>` | empty; required |
| `key set` | `--label <string>` | empty; optional |
| `bind <agent>` | `--user <id>` | empty; required |
| `bind <agent>` | repeatable `--app toolkit[:mode[:tool1,tool2]]` | `[]`; mode defaults to `full` |
| `bind <agent>` | `--toolkits a,b` | empty; each listed toolkit gets `full` scope |
| `unbind <agent>` | `--app <toolkit>` | empty; empty removes all apps |

For `--app`, mode is `full`, `read`, or `custom`; `custom` requires a
comma-separated tool list. Rebinding replaces the agent's Composio app set.

## Examples

```bash
# Add a workspace HTTP integration.
crewship integration add --name gmail --display "Google Gmail" \
  --transport streamable-http --endpoint https://mcp.example.com/gmail

# Add a local stdio integration. The CLI splits this into command + args.
crewship integration add --name local-tools --transport stdio \
  --command "npx @modelcontextprotocol/server-github"

# Bind, inspect, and resolve an agent integration.
crewship integration bind --agent daniel --server gmail \
  --credential daniel-gmail-token
crewship integration agent-bindings daniel
crewship integration resolve daniel --format json

# Create and test a crew integration, then toggle a discovered tool.
crewship integration crew create engineering --name linear \
  --transport streamable-http --endpoint https://mcp.linear.app/sse
crewship integration crew test engineering intg_abc123
crewship integration tools disable engineering intg_abc123 delete_issue

# Connect an app and bind selected Composio tools.
crewship integration composio connect gmail --user user-42
crewship integration composio bind daniel --user user-42 \
  --app gmail:read --app github:full
```

`integration test` and `integration crew test` return whatever JSON result the
server provides. For workspace HTTP integrations the server probes the
endpoint; for stdio integrations it validates the configured command. The CLI
does not launch a stdio server during this check.

For the complete command tree as emitted by the running binary, use
`crewship commands --format json`.

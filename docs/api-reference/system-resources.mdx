Crewship refreshes a host CPU and RAM reading approximately every 15 seconds.
The latest reading is shared with `/metrics` and the dashboard without a
database write. One reading per minute is stored for chart history, retained
for up to 30 days. These are **whole-server** measurements, including
processes outside Crewship. Collection starts when this version first runs;
the API does not invent readings for earlier periods or collection gaps.

## Get resource history

```http
GET /api/v1/system/resources?window=7d
```

**Authentication:** An authenticated session or API token is required. This
read-only route has no workspace-role or admin gate.

**Request:** No body. `window` is optional and accepts `24h` (the default),
`7d`, or `30d`. The corresponding chart buckets are five minutes, one hour,
and six hours. A bucket averages the readings collected within it.

**Response:** `200 OK`, `application/json`:

```json
{
  "window": "7d",
  "recording_since": "2026-09-25T12:24:00.000000000Z",
  "latest": {
    "sampled_at": "2026-09-25T12:33:00.000000000Z",
    "cpu_percent": 23.4,
    "memory_percent": 11.5,
    "memory_used_mb": 5472,
    "memory_total_mb": 47722
  },
  "series": [
    { "ts": "2026-09-25T12:00:00Z", "cpu_percent": 23.4, "memory_percent": 11.5 }
  ]
}
```

`cpu_percent` is utilization across all host CPU cores. RAM usage is based on
Linux `MemAvailable`; the `*_mb` fields use MiB. `latest` and
`recording_since` are `null` until the first reading. The full response
contains one `series` entry for every bucket in the selected window; buckets
with no reading have `null` percentages. Use `sampled_at` to detect a stale
latest reading rather than assuming the most recent bucket is current.

## Get the latest reading

```http
GET /api/v1/system/resources/latest
```

**Authentication:** An authenticated session or API token is required. This
route has no workspace-role or admin gate.

**Request:** No body or query parameters.

**Response:** `200 OK`, `application/json`, with one `latest` field containing
the same sample object shown above. `latest` is `null` before the first
successful reading. The endpoint reads the daemon's in-memory sample and
falls back to the newest stored sample during startup; it does not scan or
write chart history.

**Statuses:** `200` on success, `401` without valid authentication, and `500`
if the startup fallback cannot read the database.

**Statuses:** `200` on success, `400` for an unsupported `window`, `401` when
authentication is missing or invalid, and `500` if stored readings cannot be
loaded.

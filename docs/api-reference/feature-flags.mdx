Feature flags are an instance-global toggle surface: an instance
administrator defines a flag with a default `enabled` state, then individual
workspaces may attach an override row that flips the flag for that workspace
only.

All endpoints require authentication and workspace context. Reads are open to
any workspace role. Creating, updating and deleting a flag definition changes
every workspace, so it requires an instance administrator who is also `OWNER`
or `ADMIN` of the workspace the request is made in (see
[Who may change a definition](#who-may-change-a-definition)); a per-workspace
override requires `OWNER` or `ADMIN` of that workspace.

These are the server-side flags. The web app also has build-time
`NEXT_PUBLIC_*` switches; those are compiled into the frontend bundle and are
not listed or changed through this API.

## Effective value

The server resolves a flag for a workspace in one step
(`internal/featureflags/featureflags.go`):

1. If the workspace has an override row, its `enabled` value wins.
2. Otherwise the definition's `enabled` value applies.
3. A key with no definition row is **off**.

The `percentage` field is stored, validated (0-100) and returned, but no code
in the server evaluates it today: a flag with `enabled: false` and
`percentage: 50` is off for every workspace without an override, and a flag
with `enabled: true` is on for all of them. Treat `percentage` as a recorded
intent, not a rollout mechanism.

## Flags the server checks

These keys are read by server code on `main`. Keys not in this list can be
created and toggled, but nothing in the server reacts to them.

| `gridcraft_editor` | off | Live workbook editor sessions, cell edits and the commits feed | The server must also run GridCraft with its workbook editor (`CREWSHIP_GRIDCRAFT_ENABLED` and `CREWSHIP_GRIDCRAFT_EDITOR_ENABLED`); without both the flag has no effect |

| `artifact_dashboard_data` | off | Dashboard collection data API and its run tools | Requires `artifact_projects`; `CREWSHIP_ARTIFACT_DASHBOARD_DATA_ENABLED=true` replaces the flag |

## Who may change a definition

Definition writes (`POST`, `PATCH`, `DELETE /api/v1/feature-flags[/{key}]`)
pass two checks:

1. The route requires an instance administrator (`Only an instance
   administrator can do this` otherwise). A CLI token also needs the
   `instance:admin` scope, or no scope restriction (`Forbidden` otherwise).
2. The handler then requires `OWNER` or `ADMIN` of the workspace the request
   is made in.

So a workspace `ADMIN` who is not an instance administrator gets `403`, and so
does an instance administrator who is only `MEMBER` of the selected workspace
or who sends no workspace at all. Select a workspace you own or administer
before changing a definition.

## List Feature Flags

```
GET /api/v1/feature-flags
```

Returns every flag definition, ordered by `key` ascending. When the request
carries workspace context, each flag includes the current workspace's
override state (`override_enabled`); the field is omitted when no override row
exists for that flag.

**Auth:** Any authenticated workspace member (`read`)

**Response:** `200 OK`

```json
[
  {
    "id": "cm1abc123",
    "key": "new-dashboard",
    "description": "Roll out the redesigned dashboard",
    "enabled": true,
    "percentage": 50,
    "created_at": "2024-01-15T10:00:00Z",
    "updated_at": "2024-01-15T10:00:00Z",
    "override_enabled": false
  }
]
```

### Response Fields

| Field | Type | Description |
|---|---|---|
| `id` | string | Flag ID (CUID) |
| `key` | string | Unique flag key |
| `description` | string? | Human-readable description |
| `enabled` | boolean | Instance-global default state |
| `percentage` | integer | Recorded rollout percentage (0-100); not evaluated |
| `created_at` | string | ISO 8601 timestamp |
| `updated_at` | string | ISO 8601 timestamp |
| `override_enabled` | boolean? | Current workspace's override state; omitted when no override row exists (flag inherits the instance default) |

## Create Feature Flag

```
POST /api/v1/feature-flags
```

Inserts a new instance-global flag definition.

**Auth:** instance administrator who is also `OWNER` or `ADMIN` of the current workspace ([details](#who-may-change-a-definition))

**Request Body:**

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `key` | string | Yes | -- | Unique flag key |
| `description` | string | No | `null` | Human-readable description |
| `enabled` | boolean | No | `false` | Default state |
| `percentage` | integer | No | `0` | Recorded rollout percentage (0-100); not evaluated, see [Effective value](#effective-value) |

```json
{
  "key": "new-dashboard",
  "description": "Roll out the redesigned dashboard",
  "enabled": true,
  "percentage": 50
}
```

**Response:** `201 Created` -- the created flag object (same shape as a List item, without `override_enabled`).

| Status | Condition |
|---|---|
| `400` | Missing `key`, invalid JSON, or `percentage` outside 0-100 |
| `403` | Not an instance administrator, token lacks `instance:admin`, or not `OWNER`/`ADMIN` of the current workspace |
| `409` | A flag with this key already exists |
| `500` | Database failure |

**WebSocket event:** `feature_flag.created`

## Update Feature Flag

```
PATCH /api/v1/feature-flags/{key}
```

Partial update -- only provided fields are changed.

**Auth:** instance administrator who is also `OWNER` or `ADMIN` of the current workspace ([details](#who-may-change-a-definition))

The key itself cannot be changed; delete and recreate the flag to rename it.

| Path Parameter | Description |
|---|---|
| `key` | Flag key |

**Request Body:** All fields optional.

| Field | Type | Description |
|---|---|---|
| `description` | string | Description; empty string clears it to `null` |
| `enabled` | boolean | Default state |
| `percentage` | integer | Recorded rollout percentage (0-100) |

**Response:** `200 OK` -- the updated flag object, including `override_enabled` for the current workspace (same shape as a List item).

| Status | Condition |
|---|---|
| `400` | Invalid JSON, `percentage` outside 0-100, or no fields to update |
| `403` | Not an instance administrator, token lacks `instance:admin`, or not `OWNER`/`ADMIN` of the current workspace |
| `404` | Flag not found |
| `500` | Database failure |

**WebSocket event:** `feature_flag.updated`

## Delete Feature Flag

```
DELETE /api/v1/feature-flags/{key}
```

**Request:** No request body. The `{key}` path parameter is the feature-flag key.

Removes the flag definition. The `ON DELETE CASCADE` on the override table
means all per-workspace override rows are removed too.

**Auth:** instance administrator who is also `OWNER` or `ADMIN` of the current workspace ([details](#who-may-change-a-definition))

**Response:** `204 No Content`

| Status | Condition |
|---|---|
| `403` | Not an instance administrator, token lacks `instance:admin`, or not `OWNER`/`ADMIN` of the current workspace |
| `404` | Flag not found |
| `500` | Database failure |

**WebSocket event:** `feature_flag.deleted`

## Set Workspace Override

```
PUT /api/v1/feature-flags/{key}/override
```

Creates or replaces the current workspace's override row for the named flag.
Idempotent -- a repeated `PUT` with the same body updates the same row in
place (keyed on `UNIQUE(flag_id, workspace_id)`).

**Auth:** `OWNER` or `ADMIN` role

**Request Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `enabled` | boolean | Yes | Explicit override value. Must be present -- an absent field is rejected (a missing body must not silently disable the flag). |

```json
{ "enabled": true }
```

**Response:** `200 OK`

```json
{ "key": "new-dashboard", "enabled": true }
```

| Status | Condition |
|---|---|
| `400` | Invalid JSON, missing workspace context, or missing explicit `enabled` field |
| `403` | Not `OWNER`/`ADMIN` of the current workspace |
| `404` | Flag not found |
| `500` | Database failure |

**WebSocket event:** `feature_flag.override_set`

## Clear Workspace Override

```
DELETE /api/v1/feature-flags/{key}/override
```

Removes the current workspace's override row, reverting the flag's effective
value to the instance-global default. Idempotent -- returns `204` whether or
not an override row existed (after this call, the override does not exist).

**Auth:** `OWNER` or `ADMIN` role

**Response:** `204 No Content`

| Status | Condition |
|---|---|
| `400` | Missing workspace context |
| `403` | Not `OWNER`/`ADMIN` of the current workspace |
| `404` | Flag not found |
| `500` | Database failure |

**WebSocket event:** `feature_flag.override_cleared` (only when a row was actually removed)

All six operations require an authenticated request. The current workspace
comes from the usual workspace selection: the `workspace_id` query parameter
(the CLI adds it from your selected workspace) or the `X-Workspace-ID`
header. `GET` requires a
workspace member with the read permission. Override writes require `OWNER` or
`ADMIN` of the workspace; definition writes additionally require an instance
administrator. Every mutation returns `401` if unauthenticated or `403` when
the caller is not allowed. JSON errors use the API's standard error shape;
successful delete operations have no body.

## WebSocket events

All five events carry `{ "key": "<flag key>" }` and are sent to the workspace
the request was made in only. Other workspaces are not notified when a
definition changes; they see the new value on their next read.

A page is a declared arrangement of panels. It contains no query, no connection
string and no credential for anything it displays: a **producer** — a script, a
routine step, an agent, or an outside system holding a webhook token — pushes a
typed payload, and the panel renders the last one that arrived.

Read the [Pages guide](/guides/pages) first for what a page is and is not, the
freshness contract, and the permission model. This page is the wire contract.

Three properties hold across every endpoint below, and most of the error
responses exist to keep them true:

- **The server owns the clock and the provenance.** `produced_at`, `producer`
  and `run_id` are attached server-side. A payload carrying any of them is
  refused; a producer cannot claim to be fresher than it is.
- **Freshness is computed on read, never stored.** There is no column holding
  `fresh` or `stale`, so nothing can be written into one.
- **Identity comes from the token.** Whichever of the four write doors a push
  arrives through, the caller's identity is resolved from its credential, never
  from the body.

Implementation: `internal/api/pages_*.go`, `internal/pages` for the schemas and
validation.

## List pages

```
GET /api/v1/pages
```

**Authentication:** session cookie or CLI token. Any workspace member may list;
the response holds the pages the caller can reach — their own, their crews', and
the ones a grant names ([Issue a grant](#issue-a-grant)). A page outside that
set is absent, not present-and-locked.

**Query parameters:** `workspace_id` (required when the caller's context does
not supply one).

**Response 200** — an array of page summaries:

```json
[
  {
    "id": "pg_01H...",
    "slug": "fleet-201",
    "name": "Fleet 201",
    "description": "Line 2 uptime",
    "owner": "crew/ops",
    "owner_crew_slug": "ops",
    "panel_count": 5,
    "panel_states": { "fresh": 4, "stale": 1, "failed": 0, "never_produced": 0 },
    "last_produced_at": "2026-08-13T17:41:02Z",
    "created_at": "2026-07-02T09:12:44Z",
    "updated_at": "2026-08-11T14:03:19Z"
  }
]
```

`panel_count` counts **every** panel including sealed ones, because the grid
draws a placeholder for those and a count that skipped them would disagree with
what the reader sees. `last_produced_at` is the newest arrival across visible
panels — deliberately not `updated_at`, which is when the *spec* last changed:
a page edited an hour ago whose data last arrived a week ago must not read as
"updated today".

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Listed. |
| 400 | No workspace in context and none supplied. |
| 401 | No session or token. |
| 403 | Caller is not a member of the workspace. |

## Create a page

```
POST /api/v1/pages
```

**Authentication:** session cookie or CLI token, plus the `page.create`
capability. A MEMBER holding that capability passes; the workspace role alone
is not the answer.

**Request body** — the *parsed* spec. The CLI parses the YAML and sends JSON;
the server never parses YAML:

```json
{
  "name": "Fleet 201",
  "slug": "fleet-201",
  "description": "Line 2 uptime",
  "owner": "crew/ops",
  "panels": [
    {
      "id": "sluzby",
      "schema": "status.v1",
      "title": "Služby",
      "icon": "container",
      "owner": "crew/ops",
      "producer": "script/watch-services.sh",
      "sla": "60s",
      "span": 12,
      "tab": "Síť"
    }
  ]
}
```

`owner` is `user/<id>` or `crew/<slug>` — exactly one of the two. `span` is a
column count on a 12-column grid; **there is no height field**, a panel is as
tall as its content.

A panel may also carry `refresh` — `"on:wake"` or `"on:panels-changed"`, and
nothing else. It is the event that **runs that panel's producer**, not a
rendering hint, so it requires `producer: "routine/<slug>"`: the server cannot
execute a `script/`, call a `webhook/` producer, or dispatch an `agent/`. It
compiles to an `automations` row with `action_kind: routine`. `"on:wake"` is
additionally refused on a page that declares no `wake` gate — it could never
fire — and on a panel that declares its own gate, which is a loop. Every one of
those is a 400 naming the rule; see the
[Pages guide](/guides/pages#refresh-—-the-panel-that-pulls-itself).

**Response 201** — the created page, in the same shape [`GET
/api/v1/pages/{slug}`](#get-a-page) returns.

**Statuses:**

| Status | Condition |
|---|---|
| 201 | Created. |
| 400 | The spec is malformed, or a panel names a schema, icon, or owner that does not exist. |
| 401 | No session or token. |
| 403 | Caller lacks `page.create`, or named an owner crew they do not belong to. |
| 409 | A page with that slug already exists in the workspace. |

## Get a page

```
GET /api/v1/pages/{slug}
```

**Authentication:** session cookie or CLI token. Visibility of individual
panels is decided per panel, server-side, before serialisation.

**Path parameters:** `slug` — the page's slug.

**Response 200** — the page, its panels in spec order, and each panel's current
data:

```json
{
  "id": "pg_01H...",
  "slug": "fleet-201",
  "name": "Fleet 201",
  "owner": "crew/ops",
  "panels": [
    {
      "id": "sluzby",
      "schema": "status.v1",
      "title": "Služby",
      "icon": "container",
      "span": 12,
      "state": "fresh",
      "data": { "items": [{ "name": "api", "state": "ok" }] },
      "provenance": {
        "producer": "script/watch-services.sh",
        "run_id": "push:sluzby:412",
        "produced_at": "2026-08-13T17:41:02Z"
      }
    }
  ]
}
```

Every page object — here and in the list — also carries two booleans about its
custom application, and they answer different questions. `has_project` is true
when the page has application source at all, published or not. `has_application`
is true only while a publication is actually running. A page awaiting its first
publication has `has_project: true` and `has_application: false`; that is the
case the [publication review](#review-a-publication-candidate) exists for, so a
client deciding whether to offer the review reads `has_project`. A withdrawn
application leaves `has_project` true and `has_application` false as well.
Neither field is omitted when false.

A panel owned by a crew the caller does not belong to arrives as a **sealed
placeholder**: it keeps its id, schema and span so the page has the same shape
for everyone, and carries no data and no provenance. This is decided server-side
— nothing is hidden in the client.

An **editor** additionally receives the authored half of each panel — its
declared `actions`, `wake` gates, `on_failure` and `refresh` — because that is
what an edit form has to round-trip. A reader does not, and an absent authored
half is absent, not an empty array.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Returned. |
| 400 | No workspace in context and none supplied. |
| 401 | No session or token. |
| 403 | Caller is not a member of the workspace. |
| 404 | No page with that slug in this workspace, **or** the caller has no reach to it — see [Issue a grant](#issue-a-grant). The two are deliberately indistinguishable, so this endpoint cannot be walked to learn which pages exist. |

## Update a page

```
PATCH /api/v1/pages/{slug}
```

**Authentication:** session cookie or CLI token. The page owner, a workspace
ADMIN/OWNER, or the holder of a `write` grant.

**Request body:** the same shape as [create](#create-a-page). Panels are
reconciled against the submitted list — a panel absent from it is removed, and
its payload history goes with it.

**Response 200:** the updated page.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Updated. A new structural version is recorded. |
| 400 | Malformed spec, or an unresolvable owner/producer/routine reference. |
| 401 | No session or token. |
| 403 | Not the owner, not an admin, and holding no `write` grant. |
| 404 | No such page. |

## Push panel data

```
PUT /api/v1/pages/{slug}/panels/{panelId}/data
```

The single write path. Everything that produces a number, a status, a table or
a narrative ends here — whether it arrives directly, through a routine's
`page.write` verb, through the sidecar from inside a container, or through a
webhook.

**Authentication:** session cookie or CLI token. Authority is the **producer's**,
not a workspace role: the caller must be the panel's declared `producer`, or
hold a `produce` grant covering it.

**Request body:** the payload itself, with no envelope. It must satisfy the
panel's declared schema (`metric.v1`, `status.v1`, `table.v1`, `series.v1`,
`narrative.v1`) and is capped at 64 KiB.

```json
{ "value": 42, "unit": "ms", "delta": -3, "delta_good": "down", "sparkline": [51, 47, 45, 42] }
```

**Query parameters:** `state` — the producer's own verdict, `ok` (the default)
or `failed`. Any other value is a **400**, `fresh` and `stale` included: those
two are the server's arithmetic, and accepting them here would let a producer
declare itself fresh.

**Response 200:**

```json
{
  "accepted": true,
  "page": "fleet-201",
  "panel": "latence",
  "seq": 413,
  "state": "fresh",
  "provenance": {
    "producer": "script/ping-go",
    "run_id": "push:latence:413",
    "produced_at": "2026-08-13T17:41:07Z"
  }
}
```

A producer with no run — a script, a container agent, a webhook — carries the
push's own server-side reference `push:<panel>:<seq>` in place of a run id.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Stored. Connected viewers are notified over the page's websocket channel. |
| 400 | The payload does not satisfy the panel's schema. The message names the field and why. |
| 401 | No session or token. |
| 403 | The caller is not the panel's declared producer and holds no `produce` grant. The refusal writes a journal entry and notifies the page owner — treat it as a signal to investigate, not noise to retry past. |
| 404 | No such page, or the page has no such panel. |
| 422 | The payload exceeds 64 KiB. The rejection names the bytes attempted and the limit. |
| 429 | Faster than one push per two seconds for this panel, or over the per-minute budget. |

## List grants

```
GET /api/v1/pages/{slug}/grants
```

**Path parameters:** `slug`. **Query parameters:** `workspace_id` when the caller's context supplies none. No request body.

**Authentication:** session cookie or CLI token. The page owner or a workspace
ADMIN/OWNER.

**Response 200:**

```json
{
  "page": "fleet-201",
  "grants": [
    {
      "subject_type": "crew",
      "subject": "engineering",
      "subject_id": "crew_01H...",
      "level": "produce",
      "panels": ["rozbor"],
      "granted_by": "srba@unify.cz",
      "granted_at": "2026-08-01T08:20:11Z",
      "live": true
    }
  ]
}
```

`live` is not stored. A grant is only as wide as the human who issued it: if
that human loses access to the crew the grant names, the grant reports `live:
false` with an `inert_reason` saying so, and stops working at the same moment.
That is the only thing that makes a row inert — every level, `read` included,
decides something while its issuer still stands behind it.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Listed. |
| 400 | No workspace in context and none supplied. |
| 401 | No session or token. |
| 403 | Not the owner and not an admin. |

## Issue a grant

```
PUT /api/v1/pages/{slug}/grants
```

**Authentication:** session cookie only. **A grant is issued by a human, never
by an agent** — an agent holding `write` may rebuild a page's layout freely and
still cannot widen who reaches it, not even to another agent in its own crew.

**Request body:**

```json
{
  "subject_type": "crew",
  "subject": "engineering",
  "level": "produce",
  "panels": ["rozbor"]
}
```

| Field | Type | Description |
|---|---|---|
| `subject_type` | string | `user`, `crew`, or `agent`. |
| `subject` | string | The subject's slug or id. |
| `level` | string | `read`, `produce`, or `write`. |
| `panels` | string[] | Optional. Restricts a `produce` grant to named panels; omitted means every panel on the page. |

### What each level decides

| Level | Opens the page | Also |
|---|---|---|
| `read` | yes | nothing else |
| `produce` | yes | may push payloads into the panels it names |
| `write` | yes | may add, remove and re-arrange panels, and read the page's version history |

`read` is what the other two are built on: a principal who may rewrite a page
has to be able to open it, so every level reaches the page and the levels differ
only in what they add.

A grant widens reach to the **page**, never to a crew's data: granting a crew
`produce` on a panel does not give the grantee anything else that crew owns.

Concretely, a `read` grant makes a page appear in [`GET
/api/v1/pages`](#list-pages) and open at [`GET
/api/v1/pages/{slug}`](#get-a-page) for a subject who would otherwise get a
404 — and changes nothing else. Every panel on it stays sealed unless the
grantee's own crew membership already opened it, so a grantee can be shown a
page of nothing but sealed placeholders. That is the grant working, not
failing: they were given the board, not the numbers on it.

Without any grant a page is reached by its owner, by a workspace ADMIN/OWNER,
and by members of the crews that own its panels.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Issued, or updated in place if the subject already held one. |
| 400 | Unknown `subject_type` or `level`, missing subject, or `panels` naming a panel the page does not have. |
| 401 | No session. |
| 403 | Not the owner and not an admin, or the caller is an agent rather than a human. |

## Dispatch an action

```
POST /api/v1/pages/{slug}/panels/{panelId}/actions/{actionId}
```

**Authentication:** session cookie or CLI token, plus the right to dispatch on
this page. The request names an **action id**, never a routine: what runs is
what the panel author declared, so a caller cannot redirect a button at
something else.

**Request body:** the declared inputs, if the action declares any.

```json
{ "inputs": { "duvod": "vibrace na loži 3" } }
```

**Request headers:** `Idempotency-Key` is honoured. The key is bound to the
resolved inputs, so **retrying is safe and replaying with different inputs is
refused** with 409 rather than silently dispatching a second run.

**Response 202** — the run is *queued*, not finished:

```json
{
  "status": "SCHEDULED",
  "pending_id": "pnd_01H...",
  "fire_at": "2026-08-13T17:46:00Z",
  "deduped": false,
  "coalesced": false,
  "page": "fleet-201",
  "panel": "linka",
  "action": "restart",
  "routine": "line-restart"
}
```

`status` is `SCHEDULED`, or `DEDUPED` when an identical dispatch was already in
flight.

**Statuses:**

| Status | Condition |
|---|---|
| 202 | Queued. Watch the run for the outcome. |
| 401 | No session or token. |
| 403 | Caller may not dispatch on this page, or the panel is sealed to them. |
| 409 | The same `Idempotency-Key` was already used with different inputs. |
| 429 | Over the dispatch rate budget. |
| 503 | The dispatcher is unavailable. |

## Roll a page back

```
POST /api/v1/pages/{slug}/rollback
```

**Authentication:** session cookie or CLI token. A rollback is an edit of the
arrangement, so it runs the same gate as PATCH: owner, workspace ADMIN/OWNER,
or a `write` grant.

**Request body:**

```json
{ "to": 3 }
```

`to` is required — a rollback names the version to restore.

**Response 200:**

```json
{
  "page": { "slug": "fleet-201", "panels": [] },
  "rolled_back_to": 3,
  "version": 5,
  "dimmed": ["rozbor"]
}
```

A rollback never resurrects old panel data. A panel it brings back renders in
the "waiting for first data" state even if rows for it survive in the payload
ring; showing an old payload as current is exactly the dishonesty the freshness
contract exists to prevent. `dimmed` names those panels in the response, so the
operator who ran the rollback learns it here rather than from a blank panel
five minutes later.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Rolled back. |
| 400 | `to` missing, or naming a version that is not in the retained history. |
| 401 | No session or token. |
| 403 | Not the owner, not an admin, and holding no `write` grant. |
| 404 | No such page. |

## Export a page

```
GET /api/v1/pages/{slug}/export
```

**Path parameters:** `slug`. **Query parameters:** `workspace_id` when the caller's context supplies none. No request body.

**Authentication:** session cookie or CLI token; a caller who can see the page.

**Response 200** — a portable bundle: the spec, plus every reference it makes
to something outside itself, listed so the importer must bind them explicitly:

```json
{
  "format": "crewship.page.bundle/v1",
  "page": { "name": "Fleet 201", "slug": "fleet-201", "panels": [] },
  "references": [
    { "ref": "crew/ops", "kind": "crew", "used_by": ["sluzby"], "reason": "panel owner" }
  ],
  "metadata": { "exported_at": "2026-08-13T17:44:00Z" }
}
```

The bundle carries no data, no grants and no tokens — an export is a shape, not
a snapshot of what the page was showing.

**Statuses:**

| Status | Condition |
|---|---|
| 200 | Exported. |
| 400 | No workspace in context and none supplied. |
| 401 | No session or token. |
| 403 | Caller cannot see the page. |
| 404 | No such page. |

## Import a page

```
POST /api/v1/pages/import
```

**Authentication:** session cookie or CLI token, plus `page.create`.

**Request body:** the bundle, the slug to create, and a binding for every
reference the bundle declares:

```json
{
  "format": "crewship.page.bundle/v1",
  "page": { "name": "Fleet 201", "panels": [] },
  "references": [{ "ref": "crew/ops", "kind": "crew" }],
  "slug": "fleet-202",
  "bind": { "crew/ops": "crew/vyroba" }
}
```

An unbound reference is a **422**, not a guess. Importing a bundle that names
`crew/ops` into a workspace that happens to have a crew called `ops` would
otherwise hand a page to whoever holds that name.

**Response 201:** the created page.

**Statuses:**

| Status | Condition |
|---|---|
| 201 | Imported. |
| 400 | Unknown bundle format. |
| 422 | A reference left unbound, or a binding naming something that does not exist. The response lists each one and what would satisfy it. |
| 401 | No session or token. |
| 403 | Caller lacks `page.create`, or bound a reference to a crew they do not belong to. |
| 409 | A page with the requested slug already exists. |

**Statuses:**

## Publish a page

```
POST /api/v1/pages/{slug}/public
```

**Authentication:** session cookie. Publishing widens reach beyond the
workspace, so it is a human's decision.

**Request body** — every field optional:

```json
{ "expires_in_days": 7, "password": "…", "show_provenance": false }
```

|---|---|---|

| Status | Condition |
|---|---|
| 201 | Published. |
| 400 | `expires_in_days` out of range, or a password shorter than 8 or longer than 72 bytes. |

| 403 | Not the owner and not an admin. |
| 404 | No such page. |

## Unlock a public page

```
POST /api/v1/public/pages/{token}/unlock
```

```json

```

|---|---|

| 400 | Malformed JSON body. |

## Custom application contract

Custom Pages store a portable React/TypeScript source project separately from
live panel data. Draft edits and builds do not publish. Source operations below
require session/CLI authentication, workspace context and Page edit permission;
publication additionally requires Page ownership or workspace administration.
Application reads/actions enforce the current viewer's Page/panel reach.
Errors use JSON `{"error":"…"}`. Common statuses are `401` without authentication,
`403` without authority, `404` for an unavailable Page/resource, `500` for an
internal storage error, and `503` when required project/build/runtime services
are not configured. These endpoints are opt-in and experimental.

The supported source format is `crewship-page-source/v1` with runtime
`react-vite-typescript/v1`. `files` contains `{path, encoding, content}` entries;
encoding is `utf8` or canonical `base64`. Required files are `package.json`,
`pnpm-lock.yaml` and `index.html`. Limits: 256 files, 512 KiB decoded per file,
2 MiB decoded source, 4 MiB serialized transfer. Traversal, reserved paths,
case collisions and symlinks are rejected. The pinned compiler profile fixes
supported dependencies; project-defined install/build scripts are not executed.

### Read custom source

`GET /api/v1/pages/{slug}/project`

**Request:** path `slug`, workspace context; no body.
**Response 200:** `{revision, digest, git_commit, definition, project}`. The
project contains exact file bytes; the definition is the authored Page document.
This is an editor-only response, never the reader's application payload.
**Statuses:** `404` if no draft exists, plus the common authentication/storage
errors above. The response is `no-store`.

### Save custom source

`PUT /api/v1/pages/{slug}/project`

**Request:** `{expected_revision, project, definition?}`. Revision `0` creates
an initial draft. An optional complete `definition` replaces the draft Page
spec; omitting it preserves the previous spec (or copies the existing Page on
initialization). Public-panel flags cannot be enabled in a portable draft.
**Response 200:** `{revision, digest, git_commit, state:"draft"}` after a Git
checkpoint and atomic revision update. Live publications are unchanged.
**Statuses:** `400` malformed request, `409` revision conflict, `413` oversized
transfer, `422` invalid source/definition/references, `507` exhausted quota,
plus common errors. Authentication requires Page edit permission.

### Build custom source

`POST /api/v1/pages/{slug}/project/build`

**Request:** `{expected_revision}`; authenticated Page editor.
**Response 202:** build record `{id, source_revision, source_digest, state,
created_at}`. Completion adds `artifact_digest` or `error` and `completed_at`.
States are `running`, `ready`, `failed`, `interrupted`. One offline compiler
runs per server; this response is admission, not completed compilation.
**Statuses:** `400` malformed revision, `409` draft changed, `413` oversized
request, `429` compiler busy, `507` build-record quota, plus common errors.

### Read build preview

`GET /api/v1/pages/{slug}/project/preview`

**Request:** path `slug`; authenticated Page editor, no body.
**Response 200:** `{revision, build, runtime_url, artifact?}`. `build` is null
before the first build. A ready build includes the immutable artifact
`{format:"crewship-page-preview/v1", javascript, css, toolchain}`. This response
is `no-store`; execute only through the configured separate-site bootstrap.
**Statuses:** `404` missing draft, common errors including `503` if the worker
or required runtime isolation configuration is unavailable. Preview does not
permit SDK actions against the published application.

### List source history

`GET /api/v1/pages/{slug}/project/history`

**Request:** authenticated Page editor; optional positive `before` revision.
**Response 200:** `{revisions, next_before}` with at most 50 entries. Each entry
contains `revision`, `digest`, `git_commit`, `actor`, `actor_kind`,
`created_at`, `restorable`.
An agent-authored entry uses the agent ID as `actor`; it is not a user ID.
`actor_kind` is `user`, `agent`, `crew` or `unknown` and is the only field that
says which of those the opaque `actor` string holds.
`next_before: 0` means no further page. Metadata is `no-store`.
**Statuses:** `400` invalid cursor, plus common errors.

### Read historical source

`GET /api/v1/pages/{slug}/project/history/{revision}`

**Request:** authenticated Page editor; positive path `revision`.
**Response 200:** the same shape as the current source response, verified
against its Git checkpoint and saved Page definition.
**Statuses:** `400` invalid revision, `404` missing revision, `409` legacy
revision without a saved definition, plus common errors.

### Restore source draft

`POST /api/v1/pages/{slug}/project/restore`

**Request:** authenticated Page editor; `{revision, expected_revision}` names
the historical source and the current draft revision respectively.
**Response 200:** `{revision, digest, git_commit, state:"draft"}` for a new
checkpoint. Restore does not move the live application or erase later history.
**Statuses:** `400` malformed body, `409` stale revision or unrestorable
history, `413` oversized body, `422` invalid current references, `507` quota,
plus common errors.

### Check a publication candidate

`POST /api/v1/pages/{slug}/project/check`

**Request:** authenticated Page editor; `{build_id, expected_revision}`.
**Response 200:** `{build_id, source_revision, git_commit, artifact_digest,
checks}` after source/artifact integrity and current reference checks.
`browser_review` and `security_review` remain `required`; this is not an
automatic safety certification and does not publish or invoke actions.
**Statuses:** `400` malformed body, `409` incompatible source/build or failed
integrity checks, `413` oversized body, `422` invalid current bindings, plus
common errors.

### Review a publication candidate

`GET /api/v1/pages/{slug}/project/review`

**Request:** authenticated Page editor; path `slug`, optional positive
`publication` query parameter, no body.
**Response 200:** `{issued_at, candidate, baseline, routines, capabilities,
blockers, initial_publication}`, where `baseline` is
`{publication_version, published, definition_digest, definition,
excluded_panels, source_revision, git_commit, source_available,
source_unavailable_reason, withheld_changed, definition_diverged}` and
`candidate` is
`{revision, git_commit, source_digest, created_at, actor, build, definition}`.
`candidate` is the current draft revision with
its actor and the build of exactly that revision, and is `null` when there is
no draft, or when the draft is identical to a publication that is still
running. A withdrawn publication is not running, so an identical draft is
still a candidate: republishing it is how a withdrawal is undone.

Pass `publication=<version>` to ask what publishing that retained version
would be fenced on instead. `candidate` then describes that publication's
archived source — its source revision, checkpoint, digest, the publisher it
recorded and when — with the build it recorded, and `routines` is computed
from its archived Page definition. `candidate.actor` and `candidate.created_at`
mean the source revision's author and save time in draft mode, and the
publication's publisher and publication time in this one. That is exactly the key set a
`rollback_version` publication must send as `expected_routine_digests`; the
draft's routines are a different document's routines, and no client can
recompute the current digest of each one. `baseline` is identical in both
modes, because restoring a version replaces the same live definition. A
version that is not retained is reported as `no_candidate` and one that is
already running as `candidate_matches_live`; both keep the rest of the
snapshot, and a retained candidate stays populated so the refusal can name
which version it is about. `baseline.definition_digest` is the
sha256 of the live Page definition and is the value a publication is fenced on.
`baseline.definition` is that same live Page document, read from the same
stored row in the same request, and `candidate.definition` is the document
this candidate would make live — the draft's, or in `?publication=N` mode the
archived one that version recorded. Both come out of this one response, so the
two sides of the comparison and the digest the publication attests to describe
one instant rather than three reads of three endpoints. Compare these two
documents and not a separately fetched Page or project, or a reviewer can
approve a comparison the fence does not cover.
Panels this caller may not read are removed from both — panel visibility is
its owning crew's, and an edit grant is never a read grant — and the removal
is deliberately symmetric: a panel taken out of one document and left in the
other would be reported as added or removed by the publication, which is false
about a panel that is merely not this reader's to see.
`baseline.excluded_panels` is how many panels were withheld from the
comparison, counting a panel withheld from both documents once, so a partial
comparison can say so.
Withholding here is about what this screen renders and compares, not about
confidentiality: `GET /api/v1/pages/{slug}/project` and
`GET /api/v1/pages/{slug}/project/history/{revision}` serve the complete
unfiltered Page document to the same callers behind the same edit permission,
and the review screen reads the first of them on every render. Read
`excluded_panels` as "this comparison is partial", never as "this caller
cannot obtain that panel".
`baseline.withheld_changed` is whether any of those withheld panels actually
differs between the live definition and the candidate — added, removed,
modified, or re-pointed between a crew this caller may see and one they may
not. A count is a warning; this is the answer that settles what the consent
underneath the review can honestly cover. False means the comparison on screen
covers everything that moves and publishing stays available. True adds the
`withheld_change` blocker and the publication is refused, and nothing about
what changed is disclosed either way: the flag, and the count beside it, are
the whole of it. `routines` follows the same rule — a routine is listed only
when a panel that survived withholding declares it, so the response does not
name what it has just withheld — and `routines[].in_candidate` is therefore
exactly the fence the publication rebuilds for this caller. A routine only a
withheld panel calls is not fenced by a publisher who cannot read that panel:
the fence asks a human to attest that a value has not moved since they
reviewed it, and they never reviewed that one. A workspace administrator
reads every panel, so their list and their fence are unchanged.
`definition_digest` is unaffected by any of this, because the fence compares
the full stored document. Either document is `null` only when the stored bytes
cannot be read as a Page document, and there is then no basis for a comparison
at all; when there is no candidate, `candidate` itself is `null`.
`baseline.definition_diverged` says the live Page definition and the
definition the live publication shipped with have drifted apart — somebody
changed panels outside the application flow. It is a statement, not a refusal.
The comparison on this snapshot is derived from the current live definition
and the candidate, so it is complete regardless of what the publication once
shipped, and publishing the candidate is what ends the divergence; refusing on
it would block the only action that does. It is true in the withdrawn state
too, where `published` is `false` and nothing is running, so a note about it
must say "the live publication", never "the running application". Do not
confuse it with the `definition_moved` blocker code, which is reserved for the
publish fence tripping — a base that moved between the render and the click,
where refreshing genuinely is the cure.
`baseline.source_available:false` means the retained source for the live
publication cannot be read back — a missing comparison, never "no changes" —
and `source_unavailable_reason` says why in a sentence.
`routines` is a union: the candidate's own `call` routines and the ones the
live publication recorded, so a routine being dropped stays visible.
`routines[].in_candidate` marks the rows that belong in a publication's
`expected_routine_digests` — the candidate declares them, so the server
rebuilds and compares exactly those. Sending a row without the flag is a key
the server does not have and is refused as a `routines` conflict naming a
routine nobody moved. `routines[].state` is `unchanged`, `changed` or
`unknown`; `unknown` covers a publication that recorded no digest for a
routine and a routine that no longer resolves, and is never rendered as
agreement. `blockers[].code` is one of
`no_candidate`, `candidate_matches_live`, `build_missing`, `build_failed`,
`build_stale`, `baseline_unavailable`, `routine_unresolved`,
`definition_moved`, `withheld_change`, `not_permitted` and
`storage_unavailable`. `definition_moved` is reserved for the publish fence;
the review does not emit it.
`routine_unresolved` is emitted for every `in_candidate` routine with no
current digest: publishing such a candidate is refused, so the review says so
rather than reporting the routine as merely `unknown` beside a ready build. Missing build storage or a missing runtime origin is a
blocker, not a 503: a reviewer who cannot publish can still read the snapshot.
**Statuses:** `400` non-positive or malformed `publication`, plus common
errors. Responses are `no-store`.

### Publish or roll back an application

`POST /api/v1/pages/{slug}/project/publish`

**Authentication:** Page owner or workspace administrator; edit grant alone
is insufficient. **Request:** `{build_id, expected_revision,
expected_publication, reviewed_code:true, expected_definition_digest,
expected_routine_digests}`. Use publication `0` for the first
publication. For rollback, send `{rollback_version, expected_publication,
reviewed_code:true}` with both fence fields, and omit `build_id` and
`expected_revision`.

`acknowledged_unavailable_baseline` is optional and defaults to false. When
the live publication's retained source cannot be read back — the same
condition the review reports as `baseline_unavailable` — the publication is
refused with `409` and `conflict: "baseline"` unless it is `true`. It states
that nobody compared this candidate with what is running. It proves nothing
about the candidate itself, whose source, checkpoint, artifact and bindings
are verified either way, and the answer is recorded in the publication's
`checks` as `baseline_source` (`verified`, `unavailable_acknowledged`, or
`initial_publication`) so a receipt says which publications shipped without a
diff basis. An initial publication has no prior source and is never refused
for this reason. The server refuses by default rather than blocking outright
because retention and compaction legitimately discard old checkpoints, and a
workspace whose history was reclaimed must still be able to publish a sound
candidate — by saying so, not by having it assumed.

`reviewed_code: true` attests that the whole change was reviewed, and the
server refuses an attestation the caller cannot make. Publishing requires Page
ownership or workspace administration; seeing a panel requires membership of
that panel's owning crew or the same administration. A Page owner who is not
an administrator therefore may publish a Page carrying panels they cannot
read. Nothing there leaks and nothing bypasses authorization — the operation
was always theirs — but the claim about what was reviewed was not true of the
part that was hidden. So when a panel this caller may not read differs between
the live definition and the candidate, the publication is refused with `403`
and a sentence that says such a part exists and how many panels are withheld,
and nothing about what it is. The rollback path is included: restoring a
retained version replaces the live definition too, and the comparison is
against that version's archived declaration. Read
`baseline.withheld_changed` on the review snapshot to know in advance. This is
not a state conflict, so the body carries no `conflict` kind and refetching
changes nothing, and unlike `acknowledged_unavailable_baseline` there is no
flag that waives it: that one says nobody made a comparison, this one would
say the publisher may not see what they are signing for. A workspace
administrator reads every panel, so it never applies to one.

`expected_definition_digest` and `expected_routine_digests` are required on
both paths and are the values the reviewer was shown — read them from the
review snapshot above. The digest is 64 lowercase hex characters; the map is
keyed by routine slug and is `{}` when the candidate declares no `call`
actions. Both are compared inside the publishing transaction, before any
write, so a Page definition or a routine script that moved between review and
publication refuses the publication instead of shipping it. An exact retry
short-circuits to its original receipt before the comparison runs: the receipt
records what already happened, and the fence guards what is about to.
**Response 200:** immutable receipt `{version, build_id, source_revision,
source_digest, git_commit, artifact_digest, created_at}`. The live pointer and
Page declaration change atomically. An exact retry returns its original
receipt without rewinding a newer live publication. Rollback creates a new
publication from the old artifact and declaration; it preserves the draft and
does not undo completed routine effects.
**Statuses:** `400` invalid or conflicting fields, missing review confirmation
or a malformed fence — and a `call` action naming a routine that no longer
exists, which the authoring gate refuses ahead of the fence and therefore
without a `conflict` kind, even when the routine was deleted concurrently,
`403` publishing is not this caller's to do, or a panel
they may not read differs between the live definition and the candidate, `409`
changed draft, publication or declaration, `413`
oversized body, `422` invalid bindings, `507` publication quota, plus common
errors. A `409` body carries `conflict` — `definition`, `routines`,
`publication`, `draft` or `baseline` — naming which base moved or is missing, and a `routines` conflict
also lists the routines that moved.

### Read the live application

`GET /api/v1/pages/{slug}/application`

**Authentication:** current Page reach. **Request:** path `slug`; optional
`If-None-Match` header containing the previously returned `ETag`.
**Response 200:** `{publication, can_publish, artifact?, runtime_url?}`. An
unpublished Page returns `publication:null`. A published response includes the
immutable receipt and compiled artifact, never the source project. **304** is
returned for an unchanged ETag only after current authorization is checked;
no artifact bytes are read or retransmitted. The tag includes publication,
runtime and publishing authority. Responses are `no-store`; Studio explicitly
keeps the active artifact in memory and sends its ETag for revalidation.
**Statuses:** common errors; `404` also conceals a Page outside viewer reach.
Reading published artifacts works with the compiler disabled.

### Dispatch a published action

`POST /api/v1/pages/{slug}/application/actions/{panelId}/{actionId}`

**Authentication:** existing action-dispatch role, current Page/panel access
and routine policy. **Request:** `Idempotency-Key` header (1–128 bytes), JSON
`{publication, inputs}` at most 32 KiB. Only a stored `call` action is accepted;
there is no shell, arbitrary URL or routine-name parameter. The Studio SDK
broker obtains confirmation in the trusted host before sending this request.
**Response 202:** existing action queue receipt including `pending_id`; this
does not mean the routine completed. Keys/debounce are scoped by viewer and
publication. Publication/declaration checks and enqueue share a transaction.
**Statuses:** `400` missing key or invalid inputs, `404` inaccessible action,
`409` publication/declaration changed, `413` body too large, `429` rate limit,
plus common errors. Refresh and review the new declaration after `409`.

### Read own application action status

`GET /api/v1/pages/{slug}/application/actions/{pendingId}`

**Authentication:** only the user who dispatched this pending action, with
current access to the originating panel. **Request:** Page `slug` and the
returned `pendingId`; no body.
**Response 200:** `{pending_id, pending_status, run_id, run_status}`. Run fields
can be empty before execution. A disconnect or client timeout is not cancellation.
**Statuses:** `401` unauthenticated, `403` forbidden, `404` unavailable Page,
panel or another viewer's pending action, `500` storage failure.

### Bootstrap the isolated runtime

`GET /api/v1/pages/runtime/bootstrap`

**Authentication:** none. **Request:** no body; serve on the configured origin
on a different site from Studio. **Response 200:** fixed `text/html` bootstrap
with sandbox/CSP protections. It contains no user data, code artifacts, source
or credentials; the authorized Studio host initializes a private MessagePort.
**Status 404:** runtime origin is not configured. This is the only route that
needs exposure on the runtime reverse-proxy alias. A separate site does not
provide a portable hard browser CPU/memory limit or complete anti-exfiltration
protection; custom source still requires review.

### Publication history and withdrawal

`GET /api/v1/pages/{slug}/project/publications` requires Page edit access and
returns at most 50 receipts, `next_before`, `publication_version`, `published`
and `can_publish`. Use `?before=<version>` to paginate. Each receipt identifies
its exact source revision/build, original publisher, rollback target and any
withdrawal time. Source inspection uses the existing project-history endpoint.

`POST /api/v1/pages/{slug}/project/unpublish` requires Page ownership or workspace
administration and a body `{"expected_publication":3}`. A stale version returns
409. Withdrawal hides the application, preserves panels and history, and keeps
the version counter for future publication. Repeating the same withdrawal is
idempotent; an old successful publish retry cannot reactivate withdrawn code.

### Application panel history

`GET /api/v1/pages/{slug}/application/panels/{panelId}/history` requires readable
panel access and `publication=<mounted-version>`. Optional `limit` is 1–20;
`before` is a positive sequence cursor. The response contains `items` (sequence,
data, producedAt, state), `next_before` (0 at the end), and `publication`.
Responses are bounded to 1 MiB and never contain producer/run metadata. A stale,
withdrawn or definition-mismatched publication returns 409; an inaccessible panel
returns 404. The SDK exposes this as `getPanelHistory(panelId, {limit, before})`.

### POST /api/v1/pages/maintenance

**Authentication:** workspace OWNER or ADMIN. **Request:** JSON object; optional
`discard_history` defaults to false. Setting it to true also requires
`confirm: true` and discards optional history across the workspace. Current
drafts, live publication pointers and running builds remain protected.
**Response 200:** `compacted`, `discarded_optional_history`, and `preserved`.
**Statuses:** 400 malformed request or missing confirmation; 403 unauthorized;
503 project storage disabled; 500 storage maintenance failure.

### GET /api/v1/pages/{slug}/project/fsck

**Authentication:** Page edit access. **Request:** Page slug, no body.
**Response 200:** `healthy`, `checked_sources`, `checked_checkpoints`,
`checked_artifacts`, `checked_git_objects`, and `failures` (kind, id, error).
An unhealthy result is still HTTP 200: callers must inspect `healthy`.
This checks source, checkpoint contents, referenced artifacts and reachable Git
objects without changing them. **Statuses:** 403 no edit access; 404 unavailable
Page; 503 storage disabled or maintenance busy; 500 database/read failure.

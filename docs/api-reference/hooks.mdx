The lifecycle hook registry. Hooks fire shell commands, HTTP webhooks, or subagents on lifecycle events; this API registers them, edits them, removes them, and toggles them on or off. See the [Hooks guide](/guides/hooks).

<Note>
  All endpoints require authentication and are workspace-scoped. Non-host writes and hook deletion require workspace `OWNER` or `ADMIN`. Creating, editing or enabling a host `shell` handler requires an instance administrator with `instance:admin` token scope — see [the shell gate](#the-shell-gate).
</Note>

## Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | [`/api/v1/hooks`](#list-hooks) | List hooks (optionally filtered by crew) |
| POST | [`/api/v1/hooks`](#create-a-hook) | Register a hook |
| PATCH | [`/api/v1/hooks/{id}`](#update-a-hook) | Partially update a hook |
| DELETE | [`/api/v1/hooks/{id}`](#delete-a-hook) | Remove a hook |
| POST | [`/api/v1/hooks/{id}/enable`](#enable) | Enable a hook |
| POST | [`/api/v1/hooks/{id}/disable`](#disable) | Disable a hook |

## Reading hooks

List the registered hooks for a workspace, optionally narrowed to one crew.

### List hooks

```
GET /api/v1/hooks?crew_id=<optional>
```

**Query parameters:**

| Param | Type | Description |
|---|---|---|
| `crew_id` | string | Optional. Filter to hooks targeting this crew. Cross-tenant IDs return 404. |

**Response:** `200 OK`

```json
{
  "rows": [
    {
      "id": "hk_abc123",
      "workspace_id": "ws_123",
      "crew_id": "crw_backend",
      "event": "on_approval_requested",
      "handler_kind": "http",
      "handler_config": {
        "url": "https://hooks.slack.com/services/...",
        "method": "POST"
      },
      "matcher": {
        "severities": ["warn", "error"]
      },
      "enabled": true,
      "blocking": false,
      "created_by": "user_123",
      "created_at": "2026-03-01T09:00:00Z",
      "updated_at": "2026-04-15T14:22:00Z"
    }
  ],
  "count": 1
}
```

| Field | Type | Description |
|---|---|---|
| `rows[].event` | string | One of the 14 lifecycle events open to new writes, every one of which now has a real dispatch site — see [Currently-dispatched events](/cli/hooks#currently-dispatched-events). A row created before `pre_tool_call` was removed from that list may still show `pre_tool_call`; it lists, toggles, and can be edited (as long as the edit doesn't try to change `event` to something else invalid) — it just never dispatches, since there is no interception point before a tool runs. |
| `rows[].handler_kind` | string | `shell`, `http`, or `subagent`. |
| `rows[].handler_config` | object | Handler-specific config (URL for http, command for shell, subagent name for subagent). |
| `rows[].matcher` | object | Optional filter: `tools`, `agent_ids`, `crew_ids`, `severities`. Empty = match-all. |
| `rows[].blocking` | boolean | If true on a gate-capable `pre_*` event, a Block outcome short-circuits the triggering operation. `post_*` and `on_*` observations always dispatch asynchronously; legacy rows carrying `true` are treated as non-blocking. |

**Errors:**

| Status | Condition |
|---|---|
| 401 | No workspace. |
| 404 | `crew_id` filter points to cross-tenant crew. |
| 500 | DB error. |

## Writing hooks

### Create a hook

```
POST /api/v1/hooks
```

**Auth:** `OWNER` or `ADMIN`. `handler_kind: "shell"` requires an instance administrator with `instance:admin` token scope.

**Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `event` | string | yes | One of the 14 lifecycle events. An unknown value is a `400` whose message lists every legal one. There is no `pre_tool_call` — the platform has no interception point before a tool runs; see the [Hooks guide](/guides/hooks#events). |
| `handler_kind` | string | yes | `shell`, `http`, or `subagent`. |
| `handler_config` | object | yes* | `{"url": ...}` for http, `{"command": ...}` for shell. Optional for subagent. |
| `matcher` | object | no | `tools`, `agent_ids`, `crew_ids`, `severities`, `when`. Empty (default) matches every event. |
| `crew_id` | string | no | Scope to one crew. Omit for workspace-wide. Cross-tenant IDs return `404`. |
| `blocking` | boolean | no | Default `false`. Valid only for gate-capable `pre_*` events. `post_*` and `on_*` events are asynchronous observations and reject `true`. |
| `enabled` | boolean | no | Default **`true`**. Pass `false` to register without arming. |

```json
{
  "event": "pre_agent_start",
  "handler_kind": "http",
  "handler_config": { "url": "https://hooks.slack.test/services/XXX" },
  "crew_id": "crw_backend",
  "blocking": true
}
```

**Response:** `201 Created`, body is the created hook in the same shape [list](#list-hooks) returns per row.

**Errors:**

| Status | Condition |
|---|---|
| 400 | Unknown `event` (message lists the 14 valid names); `blocking: true` on an observation event; unknown `handler_kind`; missing `handler_config.url` / `.command`; malformed JSON. |
| 401 | Not authenticated / no workspace. |
| 403 | Missing workspace management authority, or missing instance administrator authority/scope for a host hook. |
| 404 | `crew_id` names a crew outside your workspace. |

Writes an `audit_logs` row with action `hook.create`.

<Warning>
  A hook whose `event` is misspelled would insert cleanly (the `hooks_config` schema constrains `handler_kind`, not `event`), never match the dispatcher's query, and silently never fire — while still listing and toggling like a healthy hook. That is why an unknown event is a hard `400` rather than a warning.
</Warning>

### Update a hook

```
PATCH /api/v1/hooks/{id}
```

**Auth:** `OWNER` or `ADMIN`. An instance administrator is required to set `handler_kind: "shell"`, edit an existing host hook, or enable it.

Semantics are **patch, not put**: only the fields present in the body change. An omitted field keeps its current value, so `{"event": "pre_agent_start"}` does not clear the matcher, the blocking flag, or the enabled flag. In particular, a body that never mentions `event` at all leaves it untouched — including on a legacy row whose `event` is `pre_tool_call`, which stays editable for every other field. Consequently, changing a blocking `pre_*` hook to a `post_*` or `on_*` event must also send `"blocking": false`; otherwise the merged observation hook is rejected with `400`.

Accepts the same fields as [create](#create-a-hook), all optional.

**Response:** `200 OK` with the updated hook.

**Errors:** as create, plus `404` when the hook is outside your workspace (cross-tenant IDs are indistinguishable from missing ones).

Writes an `audit_logs` row with action `hook.update`.

### Delete a hook

```
DELETE /api/v1/hooks/{id}
```

**Auth:** `OWNER` or `ADMIN`. The request has no body.

**Response:** `200 OK`

```json
{ "id": "hk_abc123", "deleted": true }
```

**Errors:** `401` unauthenticated, `403` for a non-`OWNER`/`ADMIN`, `404` when the hook is not in your workspace.

Deletion is permanent. To stop a hook firing while keeping its definition, use [disable](#disable) instead. Writes an `audit_logs` row with action `hook.delete` carrying the deleted hook's event, handler kind, and crew scope — after the delete there is nothing left to reconstruct it from.

### The shell gate

`handler_kind: "shell"` runs a command on the crewshipd **host**, outside container isolation, with the privileges of the `crewship` process. That is a strictly larger grant than the rest of the ADMIN surface, so it needs an instance administrator — on create, update and enable. An `http` hook PATCHed into a `shell` hook is the same grant by a longer road, and is refused for the same reason.

The handler verifies instance authority and token scope. `hooks.Register`, `hooks.Update` and `hooks.SetEnabledAuthorized` also require the caller to supply verified authority; they cannot infer identity themselves. Runtime dispatch additionally checks approval of the exact stored configuration. Restore paths clear imported approval.

## Toggling hooks

Flip a hook on or off. Both transitions emit `system.hook_toggled` into the journal with the actor's user ID.

<Warning>
  Enabling a hook can invoke shell commands, hit third-party webhooks, or dispatch subagents -- enabling a host shell hook requires an instance administrator. Workspace `OWNER` or `ADMIN` can disable it to stop execution. Non-host toggles retain the workspace role gate.
</Warning>

### Enable

```
POST /api/v1/hooks/{id}/enable
```

**Path parameters:** `id` is the hook ID. The request has no body.

**Auth:** Enabling a host shell hook requires an instance administrator and `instance:admin` token scope. Non-host hooks require workspace `OWNER` or `ADMIN`. Disabling host hooks is allowed for either workspace management authority or an instance administrator.

**Response:** `200 OK`

```json
{ "id": "hk_abc123", "enabled": true }
```

**Errors:**

| Status | Condition |
|---|---|
| 400 | Missing `id`. |
| 401 | Not authenticated. |
| 403 | Not OWNER/ADMIN. |
| 404 | Hook not in your workspace. |
| 500 | DB error. |

Emits `system.hook_toggled` into the journal with the actor's user ID.

---

### Disable

```
POST /api/v1/hooks/{id}/disable
```

**Path parameters:** `id` is the hook ID. The request has no body.

Same auth rules, same response shape with `"enabled": false`.

**Errors:** `401` when unauthenticated, `403` for a non-`OWNER`/`ADMIN`,
`404` when the hook is outside the workspace, and `500` on a database error.

## Registration from Go

In-process provisioning code can skip HTTP and call the store directly. This is the same function the endpoints above call — there is one write path, not two:

```go
const allowedShell = false // flip to true only after verifying instance administrator authority
_, err := hooks.Register(ctx, db, hooks.Hook{
    WorkspaceID: ws,
    Event:       hooks.EventOnApprovalRequested,
    HandlerKind: hooks.HandlerKindHTTP,
    HandlerConfig: map[string]any{
        "url": "https://...",
    },
    Enabled: true,
}, allowedShell)
```

The trailing `allowedShell bool` argument is the gate on `HandlerKindShell`: pass `false` without verified instance administrator authority — the function returns `hooks.ErrShellHookNotAllowed` if the hook is a shell kind and this flag is `false`. HTTP / subagent hooks are unaffected by the flag. `Register` also returns `hooks.ErrUnknownEvent` for an event outside the declared fifteen.

`hooks.Update(ctx, db, workspaceID, hook, allowedShell)` is the equivalent for edits. It takes the **full** desired hook (not a patch — merging is the HTTP layer's job), pins `id` + `workspace_id` from its arguments so a struct naming another workspace cannot move the row, and never rewrites `created_at` / `created_by`.

## Host hook review after upgrade or restore

Host shell hooks require instance administrator authority, not workspace ownership.
Existing host hook definitions are preserved but disabled on upgrade because prior
versions did not record historical instance authority. The audit log records
`hook.host_review_required` without recording command contents. A restored host
hook also loses imported approval and stays disabled until local review.

An instance administrator must inspect the current command and configuration,
then use **Enable** in Lifecycle hooks or `crewship hooks enable ID` with the
appropriate workspace and an instance-admin session/token (`instance:admin`).
`host_review_required` in list/detail responses identifies pending review.
Creating or editing a host hook requires the same authority. The default global
lifecycle pause still prevents execution; it is not an authorization bypass.
Container startup hooks are a separate feature and are unchanged.

## Shared fixture and invariant

In one workspace create human `H1` and human `H2`, agents `A` and `B`, and distinct canary strings in each chat, file, artifact, memory item, and log. Give both humans ordinary workspace membership; grant only `H1` access to `A` and project `P1`, only `H2` access to `B` and project `P2`. Also create two *different private conversations with A*, one for each human, while granting both humans `A:chat`. Positive controls prove each human can use their own objects. Negative controls assert no object bytes, title, filename, count, search hit, metadata, run ID, or stream event for the other human. Repeat reads with direct IDs and pagination/search/count options; reject before IPC or storage access where possible. Run once with grants revoked after an already-open stream and after a job is queued. Expected response codes must be fixed by the new policy contract; a filtered list is empty and an unauthorized direct object lookup is an indistinguishable deny (usually 404), never a successful empty proxy response.

Use real migrated SQLite and handler/router middleware for HTTP tests. Seed grants via their public/store API, not a mocked allow boolean. Record the request user, agent, project, chat, run, and policy version in the assertion so a test cannot pass only from a workspace mismatch. Agent/crew shared resources must receive an explicit classification; do not silently treat them as private or public.

## Separate Linux/process gate

The HTTP/WS matrix above says nothing about what a live agent process can read. Keep agent UID 1001 and sidecar UID 1002 unchanged. On disposable isolated runtimes, use **synthetic secrets** and an actual shell under the agent process identity: `A/H1` tries to read B/P2 mount paths, another H2 run's HOME/checkpoint/memory and credentials, follow symlinks, inspect `/proc`, call sidecar IPC, and reach forbidden network services. Deny or prove absence at the mount/network boundary. Repeat with the same agent A serving two private humans. A read-only mount is checked for both write rejection and absence of a writable alias. Existing crew container sharing UID 1001 is a trusted shared mode, not evidence for this gate. Do not mark A2/B complete from API tests alone.

## Reusable test scaffolding and highest-risk gap

Use `setupTestDB`, `seedTestUser`, `seedTestWorkspace` (`internal/api/router_test.go`) for a migrated database; `seededDB` (`internal/ws/channel_auth_extra_test.go`) for channel matrix; `newInternalHybridFixture` (`internal/api/memory_hybrid_search_internal_test.go`) and `memMutFixture` (`memory_mutation_test.go`) for sidecar-bound memory; `covAsgRig` (`assignments_run_cov_test.go`) and `delegationFixture` (`delegation_limits_test.go`) for assignment paths; `newTestHubForStream` (`run_stream_handler_test.go`) for SSE. Extend fixtures to two humans in the *same* workspace and two private chats with the *same* agent.

The highest-risk missing coverage is that shared-agent private conversations can leak across **three independent routes**: list/search/count, direct message proxy, and `session:{chatID}` WebSocket subscription. The next risk is file/API success masking the common-UID shell path. Make the first gate a single two-human fixture exercised across these routes, then add the process test as a separate required release gate. At writing, this document has not run new tests or a live smoke.

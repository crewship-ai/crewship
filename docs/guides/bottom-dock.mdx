# Bottom dock

The **Crews** page (`/crews`) has a **collapsible dock** pinned to the bottom of the viewport. It's collapsed to a thin tab strip by default — click any tab to expand it (320 px), drag the top edge to resize between 160 and 900 px, and it remembers your height.

The dock is **context-aware**: its tabs are scoped to the agent or crew selected in the explorer or on the canvas — workspace-wide when nothing is selected — so what you see is always the live layer of *that* thing. Selecting a different agent or crew re-scopes every tab.

The dock is mounted on the Crews page only. **Issues** has none since the Harbor 2 layout: an issue's activity, runs, comments and pull requests are on its own page (`/issues/<id>`), and live work across issues is on [Activity](/guides/activity). Routines and Activity have none either — a routine's runs live in its **History** view and its schedule in its **Overview** (see [Routines](/guides/routines)), and a run's log is the **Runs** tab of the [Crew Journal](/guides/crew-journal) (`/journal?tab=runs`).

## What the dock shows

Scoped to the selected agent or crew container:

| Tab | What it shows |
|-----|----------------|
| **Terminal** | Interactive shell into the crew container (xterm over WebSocket) |
| **Files** | Browse + edit the agent's home dir or the crew's shared tree |
| **Messages** | The agent's peer inbox — questions, escalations, approvals |
| **Exec Log** | The agent's container log |
| **Docker** | Containers for the workspace + status |
| **YAML** | Read-only projection of the agent/crew record |

## CLI parity

An issue's activity, runs and comments have matching CLI commands, so an agent can pull the same data without the UI:

```bash
crewship issue runs CRE-142          # runs triggered by an issue
crewship issue comments CRE-142      # issue discussion thread
crewship issue activity CRE-142      # issue timeline
crewship routine logs run_abc123 --full   # full per-run journal timeline (the routine's Logs, no longer a dock tab)
```

See [Issues & triage](/api-reference/issues) and [Routines](/guides/routines) for the underlying endpoints.

# Bottom dock

The **Crews** page (`/crews`) has a **collapsible dock** pinned to the bottom of the viewport. It's collapsed to a thin tab strip by default — click a tab, or **Terminal** in the top bar, to expand it (320 px); drag the top edge to resize between 160 and 900 px, and it remembers your height. Phones have no dock.

The dock is **context-aware**: its tabs are scoped to the open crew or agent, so what you see is always the live layer of *that* thing. Opening a different crew or agent re-scopes every tab.

The dock is mounted on the Crews page only. **Issues** has a drawer of its own with the same chrome (below); Routines and Activity have none — a routine's runs live in its **History** view and its schedule in its **Overview** (see [Routines](/guides/routines)), and a run's log is the **Runs** tab of the [Crew Journal](/guides/crew-journal) (`/journal?tab=runs`).

## What each page shows

<Tabs>
  <Tab title="Crews & Agents">
    Scoped to the selected agent or crew container:

    | Tab | What it shows |
    |-----|----------------|
    | **Terminal** | Interactive shell into the crew container (xterm over WebSocket): in `/crew/shared` for a crew, in `/crew/agents/<slug>` for an agent. Viewers cannot open one. |
    | **Files** | Browse + edit the agent's home dir or the crew's shared tree |
    | **Logs** | An agent's container log (agents only) |

    Messages from teammates are on the agent's **Overview**; a crew's containers, image and services are on its **Environment** tab.
  </Tab>
  <Tab title="Issues">
    The bottom drawer of `/issues`, scoped to the issue in focus:

    | Tab | What it shows |
    |-----|----------------|
    | **Activity** | Timeline of everything that happened on the issue — assignments, status changes, escalations, runs |
    | **Runs** | Every run triggered by the issue, with status + duration. CLI: `crewship issue runs <id>` |
    | **Changes** | Diff produced by the work (see [Changes](#changes-tab)) |
    | **Comments** | Discussion thread on the issue (humans + agents). CLI: `crewship issue comments <id>` |
    | **Spec** | The issue's YAML record |
    | **Docker** | Environment the work is running in |

    The old agent-scoped **Messages / Exec Log** tabs were removed from issues — they showed nothing when no agent was selected. Comments (issue discussion) is a different thing from Messages (an agent's peer inbox).
  </Tab>
</Tabs>

## Changes tab

The **Changes** tab on the issues drawer shows the diff the issue's work produced. It's computed on demand — there's no stored snapshot — and degrades to a calm "not wired up for this workspace yet" note when the diff source isn't available, rather than erroring.

<Note>
The diff source (working-tree changes vs. a diff against the base branch) is a workspace-level decision. Until it's configured the tab stays in its idle state; the rest of the dock is unaffected.
</Note>

## CLI parity

The dock's read tabs have matching CLI commands, so an agent can pull the same data without the UI:

```bash
crewship issue runs CRE-142          # runs triggered by an issue
crewship issue comments CRE-142      # issue discussion thread
crewship issue activity CRE-142      # issue timeline
crewship routine logs run_abc123 --full   # full per-run journal timeline (the routine's Logs, no longer a dock tab)
```

See [Issues & triage](/api-reference/issues) and [Routines](/guides/routines) for the underlying endpoints.

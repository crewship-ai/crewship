<Note>
Revert and proposal review are off by default
(`NEXT_PUBLIC_DOCUMENT_REVIEW_ACTIONS=true`) until the matching server
endpoints ship. History browsing and compare do not need them.
</Note>

## Compare

Open **History**, pick a revision, then **Compare with saved version**. Each changed
block is labelled **Added**, **Removed**, **Changed** or **Moved** with its
before and after text. The comparison is against the last saved version; unsent
edits are not included, and the page says so. Comparing never edits the document.

## Revert a change

**Revert this change** undoes only the change recorded at that checkpoint and
keeps later work. If later work touches the same blocks, nothing changes and the
conflict is shown. (Restoring a whole earlier version is a separate action with
its own confirmation, see the CLI guide for `doc restore`.)

Revert asks for confirmation and is offered only to people who can edit the
document. If you have unsent edits, revert and accept stay disabled until the
edits are confirmed; you can download them from the same place. The request
names the revision you were reviewing; if the document moved on, a revision is no
longer retained, or your access changed, the result says so and nothing is
changed.

If the connection drops or the server answers with an error, the result is
**unknown**: the action may or may not have completed. Check the document
history, then use **Try again (same request)**; the repeat carries the same
request key, so it cannot apply twice.

Compare also reports formatting and attribute changes (a link target, a heading
level) and tells blocks apart by their stable ID, or by identical content when a
block has none.

## Proposals

Where an agent prepared a proposal instead of editing directly, it waits under
**Proposals** below the document. Nothing in a proposal reaches the document
until someone accepts it.

1. Under **Proposals**, choose a proposal. Each entry shows its author, its
   state and the revision it was based on, for example
   *Crew agent · open · revision 12*.
2. Read the comparison of **the original** with **the proposal**. It uses the
   same change labels as **Compare**.
3. Choose **Accept proposal**, or **Reject proposal** and then
   **Confirm reject** (**Keep reviewing** goes back).

Accepting applies the whole proposal or nothing. If the document changed since
you opened the proposal, nothing is applied and the conflict is shown. As with
revert, accept stays disabled while you have unsent edits, and a dropped
connection gives an unknown result that you retry with
**Try again (same request)**. Readers can compare but not decide; they see
*You can compare this proposal but not decide on it.*

Proposals need the same `NEXT_PUBLIC_DOCUMENT_REVIEW_ACTIONS=true` build flag
as revert, and the server endpoints that serve them. Without the endpoints the
panel shows *Proposals could not be loaded.*

This section covers the Docs editor. Native Word documents and Sheets in
Artifacts have no proposals; an agent task there saves versions directly. See
[Word and Sheet editing](/guides/artifacts/word-and-sheet).

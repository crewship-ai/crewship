# Document persistence boundary

The trusted document service validates supported Yjs snapshots, updates, and
ordered block projections before calling `Store`. Go treats binary state as
opaque; it never attempts a CRDT merge. The service must keep Yjs garbage
collection disabled so pinned checkpoint state remains restorable.

Every document operation receives an authorization callback. It must verify the
current page is active, belongs to the requested workspace, and grants the
request actor the required capability. The callback runs after SQLite's writer
fence is acquired and before any read, receipt replay, or mutation. Only its
returned actor is written to audit records. The composite foreign key independently
enforces the page/workspace relationship. `InvalidateLeases` is the boot-only
system exception: call it before accepting requests from a new service process.

A successful commit atomically advances the durable head revision, inserts an
incremental update, updates the projection, and writes the receipt/audit record.
The baseline snapshot changes every 32 updates or 64 KiB of accumulated updates;
only replay updates covered by that snapshot are removed. Checkpoints retain
full validated snapshots independently. Restore advances the revision and epoch,
invalidates the live writer, and replaces the baseline with the pinned snapshot.
Receipts and checkpoints are never pruned to satisfy a quota.

Writer leases have random tokens and epochs. An unexpired lease cannot be
stolen, even by the same owner. Renewal and release require the live token.
`Commit` requires a live lease; retries across process/epoch changes first use
`LookupReceipt` with the original semantic fingerprint generated by the trusted
service. Full commit payload digests independently reject mismatched commit ID
reuse. All receipt lookups require current authority and the original actor.
Use `RestoreRequestWithFingerprint` with a stable request ID and original
semantic fingerprint for service restore retries.

Default limits: 1 MiB current snapshot plus projection, 256 KiB replay log,
16 MiB pinned checkpoint payloads per document, 10,000 new operations per rolling 600-second server-time window per document,
and 128 documents per workspace (configurable). Every audit/retry receipt remains
retained for the Page lifetime; the window is a throughput limit, not receipt
retention. Exact authorized retries bypass admission without refreshing time.
Temporary admission returns `document_rate_limit`; byte/history limits remain
`document_quota`. Receipt storage growth is not solved by this cut. `Stats` reports logical
payload retention, excluding SQLite page allocation and WAL overhead.

The editor generation is separate from writer lease epochs. Go-authority and
Node-process identities additionally prevent a rolled-back physical backup from
reusing an old public editor epoch. Service recovery fences all writer tokens
only after Node owns its configured private listener; a bounded boot ID makes
an uncertain recovery retry idempotent. All externally admitted document
mutations pass the expected generation into the writer transaction.
